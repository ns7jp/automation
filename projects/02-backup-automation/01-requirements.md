# 01. 要件定義書

案件No.2「定期バックアップ自動化&世代管理ツール」の要件を定義する。

## 1. 背景・目的

同社が運用するWebサーバーのコンテンツを手動でバックアップしていたところ、担当者がバックアップを取り忘れ、データ消失の危機があった。

この問題を解決するため、以下を目的として自動化ツールを構築する。

- バックアップ取得を**人の記憶に頼らず自動化**する
- 古いバックアップを**手動で消さなくても勝手に整理される**仕組みにする
- 失敗時には**気づける**仕組み(ログ・通知)を用意する

## 2. 機能要件

| 要件ID | 要件名 | 詳細 | 優先度 |
|---|---|---|---|
| FR-01 | 対象ディレクトリの圧縮バックアップ | 指定ディレクトリ(例: `/var/www/html`)を`tar.gz`形式で圧縮し、バックアップ用ディレクトリへ保存する | 必須 |
| FR-02 | 日付入りファイル名 | バックアップファイル名に取得日(`YYYYMMDD`)を含め、いつ取得したバックアップか一目でわかるようにする | 必須 |
| FR-03 | 世代管理(自動削除) | 7世代(7日分)を超えた古いバックアップを`find`コマンドで検出し自動削除する | 必須 |
| FR-04 | 定期自動実行 | `cron`を用いて毎日AM3:00に自動実行する | 必須 |
| FR-05 | 実行ログの記録 | バックアップの開始・成功・失敗・削除内容をログファイルに記録する | 必須 |
| FR-06 | 失敗時の管理者通知 | バックアップ失敗時に、Slack Webhookへ通知を送信する | 必須 |
| FR-07 | 空き容量の警告(発展要件) | バックアップ先の使用率が閾値(既定80%)を超えた場合に警告ログとSlack通知を出す | 推奨 |
| FR-08 | 設定の外部化 | 対象ディレクトリ・保存先・世代数・閾値などを設定ファイル(`backup.conf`)に分離し、スクリプト本体を変更せずに変更可能にする | 推奨 |

## 3. 非機能要件

| 要件ID | 分類 | 要件 | 補足 |
|---|---|---|---|
| NFR-01 | 可用性 | バックアップ処理の失敗がシステム全体(Webサーバー本体)に影響しないこと | スクリプトは対象を読み取るだけで、対象ディレクトリ自体には書き込みを行わない |
| NFR-02 | べき等性(=同じ処理を何度実行しても結果が同じになる性質) | 同日に複数回実行しても、同名ファイルが上書きされるだけでエラーにならないこと | ファイル名に日付までしか含めないため、1日1世代という前提を明確にする |
| NFR-03 | セキュリティ | Slack Webhook URLなどの秘匿情報を含む設定ファイルは、rootまたは実行ユーザーのみ読み取り可能にすること | `chmod 600 backup.conf` を徹底する |
| NFR-04 | 保守性 | 設定(config)とロジック(script)を分離すること | 運用担当者が設定変更のみで対応できるようにする |
| NFR-05 | 監視性 | ログにはタイムスタンプとログレベル(INFO/WARN/ERROR)を付与し、後から追跡できること | 障害発生時の原因調査を容易にする |
| NFR-06 | ログ管理 | ログファイルが際限なく肥大化しないこと | `logrotate`で世代管理する(30日分を目安) |
| NFR-07 | 復旧目標(RPO) | データ消失時に許容できるデータ損失は最大1日分とする | 日次バックアップのため、RPO(Recovery Point Objective=どの時点まで遡ってデータを復旧できるようにしておくかという目標)は24時間 |

## 4. スコープ外(今回は対応しない範囲)

- リモートストレージ(S3やNASなど)への転送・二重化
- バックアップからの自動リストア(復元)機能の実装
- 差分バックアップ・増分バックアップ(今回は毎回フルバックアップを取得する方式とする)
- Webサーバーのデータベース(MySQL等)のバックアップ(対象はファイルシステム上の静的コンテンツのみ)

## 5. 検証環境

実際の構築・動作確認は、以下の環境を想定して行う(ローカルVMまたはコンテナでの再現を想定)。

| 項目 | バージョン等 |
|---|---|
| OS | Ubuntu Server 22.04 LTS |
| シェル | bash 5.1.16 |
| tar | GNU tar 1.34 |
| findutils(find コマンド) | 4.8.0 |
| coreutils(df, date等) | 8.32 |
| cron | cron 3.0pl1(Ubuntu標準) |
| curl | 7.81.0 |
| logrotate | 3.19.0 |
| 実行ユーザー | root、またはバックアップ対象への読み取り権限と`crontab`登録権限を持つ運用ユーザー |
| バックアップ対象例 | `/var/www/html`(同社が運用するWebサーバーのコンテンツを想定) |

> 💡 バージョンが多少前後しても、本ドキュメントで使用するオプション(`tar czf`, `find -mtime`, `df --output`など)は標準的なGNU実装であれば同様に動作する。
