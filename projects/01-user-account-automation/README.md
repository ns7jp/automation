# 案件No.1: Linuxユーザーアカウント一括作成・管理自動化ツール

## 難易度

★☆☆☆☆(入門)

シェルスクリプトの基本文法(変数・条件分岐・ループ)と、Linuxのユーザー管理コマンドの使い方を一通り理解していれば取り組める難易度です。ポートフォリオの最初の1本として、「手作業をスクリプトで自動化する」という一番シンプルな成功体験を積むことを目的とした案件です。

## 想定依頼元・背景

| 項目 | 内容 |
|---|---|
| 依頼元 | 株式会社サンプル商事(従業員50名規模の中小企業・架空社名) |
| 部署 | 情報システム部門(担当者1名体制) |
| 課題 | 新入社員が入社するたびに、Linuxファイルサーバーへのユーザーアカウント作成を手作業(`useradd`コマンドを1件ずつ手入力)で行っており、入力ミスや作業漏れ(パスワード未設定・部署違いなど)が発生している |
| 要望 | 人事から届くCSVファイルを渡すだけで、アカウント作成が一括・確実に終わるツールがほしい |

情報システム担当者が1人しかいない中小企業では、こうした「定型作業だが手間とミスのリスクが大きい業務」をシェルスクリプトで自動化する場面が非常に多くあります。本案件はその典型例です。

## 依頼内容(要求仕様)

- 氏名・ユーザー名・所属部署(グループ)・初期パスワードが記載されたCSVファイルを読み込み、Linuxユーザーアカウントを一括作成すること
- 既に存在するユーザー名はスキップし、その旨をログに記録すること
- 作成したユーザーには初回ログイン時にパスワード変更を強制すること(`chage -d 0` 等を利用)
- 処理結果(成功/失敗/スキップ)を実行ログとして記録すること
- 誤操作防止のため、実際には変更を加えずに動作確認だけできる「ドライランモード(`--dry-run`)」を用意すること
- root権限が必要な処理であるため、一般ユーザーで実行された場合はエラーメッセージを出して終了するチェックを入れること

## 使用技術・ツール

| 分類 | 技術・コマンド |
|---|---|
| シェル | Bash(`#!/bin/bash`) |
| ユーザー管理コマンド | `useradd` / `usermod` / `groupadd` / `chpasswd` / `chage` / `getent` |
| CSV読み込み | `while read` + `IFS`(区切り文字指定) + プロセス置換 |
| 引数処理 | `getopts`(短いオプション)+ 長いオプションの変換処理 |
| ログ出力 | `tee -a`(標準出力とログファイルへの同時出力) |
| 権限制御 | `$EUID` によるroot権限チェック |
| 検証環境 | Ubuntu Server 22.04 LTS |

## この案件で身につくスキル

- Bashシェルスクリプトの基本文法(変数、条件分岐、ループ、関数、コマンドライン引数処理)
- Linuxのユーザー・グループ管理コマンド(`useradd`、`groupadd`、`chpasswd`、`chage`)の実務的な使い方
- CSVのような構造化データをシェルスクリプトで扱う方法
- 「べき等性(=同じ処理を何度実行しても結果が変わらない性質)」を意識した設計の考え方
- 誤操作を防ぐための安全装置(ドライランモード・権限チェック)を組み込む設計思想
- 実行ログを残し、後から処理結果を追跡できるようにする運用の基本

## 面接でアピールできるポイント(3つ、実際に話すセリフ例つき)

1. **「なぜドライランモードを作ったか」を語れる**

   > 「単にユーザー作成スクリプトを書くだけでなく、"誤って本番環境に実行してしまう事故" を防ぐために `--dry-run` オプションを実装しました。実務では、変更を伴うスクリプトは必ず事前にドライランで影響範囲を確認してから本番実行する、という運用が一般的だと調べて分かったので、その考え方を最初から設計に取り入れています。」

2. **べき等性(idempotency)を意識した設計ができる**

   > 「スクリプトを誤って2回実行しても、既存ユーザーを`getent`で検知して自動的にスキップする作りにしています。人為的な多重実行があってもシステムの状態が壊れない、"何度実行しても安全" なべき等性のある設計を意識しました。実際に同じCSVで2回実行し、2回目は全件スキップされることをログで確認しています。」

3. **「なぜroot権限チェックを入れたか」を運用目線で語れる**

   > 「`useradd` などは root権限がないと失敗しますが、権限エラーのメッセージは初心者には分かりにくいものです。そこで処理の最初に `$EUID` で実行ユーザーをチェックし、"sudoで実行してください" という分かりやすい日本語エラーを出すようにしました。使う人(将来の自分や他の担当者)がすぐに原因に気づけるようにする、という運用者目線を意識しています。」
