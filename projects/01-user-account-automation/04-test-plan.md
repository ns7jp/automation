# テスト仕様書: Linuxユーザーアカウント一括作成・管理自動化ツール

対象案件: [README.md](./README.md) / 要件: [01-requirements.md](./01-requirements.md)

## 1. テスト方針

- 正常系(想定通りの入力に対して想定通りの結果になること)と、異常系(誤った入力・実行方法に対して安全に失敗すること)の両方を確認する。
- すべてのテストは [03-build-guide.md](./03-build-guide.md) の手順で構築した検証環境(Ubuntu Server 22.04 LTS)で実施する。
- 破壊的な操作(ユーザー作成)を伴うため、各テストケースの前提条件は「クリーンな状態(該当ユーザー・グループが存在しない)」を基本とする。テスト実施後は `userdel -r` / `groupdel` で後片付けを行う。

## 2. テスト用CSVサンプル

以降のテストケースでは、[src/users.csv.sample](./src/users.csv.sample) をベースとし、一部のテストケースでは以下のような不正データを含む専用CSVを別途用意する。

```text
氏名,ユーザー名,部署,初期パスワード
テスト太郎,,eigyo,Pass1234!
不正 花子,Bad-Name!,soumu,Pass1234!
新規 一郎,ichiro_s,soumu,Pass1234!
```

## 3. 正常系テストケース

| ID | テスト内容 | 前提条件 | 操作手順 | 期待結果 | 関連要件 |
|---|---|---|---|---|---|
| TC-01 | CSVからの新規一括作成 | `yamada_t`等4ユーザーが未作成。`users.csv.sample`を`users.csv`として配置済み | `sudo ./create_users.sh -f users.csv` を実行する | 4ユーザーすべてが作成され、ログに`成功: 4件 / スキップ: 0件 / 失敗: 0件`と出力される。`id yamada_t`でユーザー情報が確認できる。終了ステータスが`0`である | F-01, F-02, F-05 |
| TC-02 | 所属グループの自動作成 | 対象4部署(`eigyo`/`soumu`/`kaihatsu`/`keiri`)のグループが未作成 | TC-01と同じコマンドを実行する | `getent group eigyo`等で各グループが新規作成されていることを確認できる。ログに`グループ ○○ を新規作成しました。`が出力される | F-03 |
| TC-03 | 既存グループの再利用 | 作成対象ユーザーの部署名に、すでに存在するグループ名(例: OS標準の`games`グループ)を指定したCSVを用意 | `sudo ./create_users.sh -f group_reuse.csv` を実行する | `groupadd`が実行されず(ログに新規作成メッセージが出ない)、既存グループにそのままユーザーが所属する。`id`コマンドでgidが既存グループと一致する | F-03 |
| TC-04 | 初回ログイン時パスワード変更の強制 | TC-01実行済み(`yamada_t`作成済み) | `chage -l yamada_t` を実行する | `Last password change` 等の項目が `password must be changed` と表示される | F-06 |
| TC-05 | 初期パスワードの設定確認 | TC-01実行済み | `yamada_t` に設定した初期パスワード(`ChangeMe123!`)でログインを試みる(`su - yamada_t`等) | パスワード入力後にログインが成立し、直後にパスワード変更を求められる | F-05, F-06 |
| TC-06 | 既存ユーザーのスキップ(べき等性) | TC-01実行済みの状態で、同じ`users.csv`を再度実行 | `sudo ./create_users.sh -f users.csv` を実行する | 4件すべてが`[SKIP]`として記録され、`成功: 0件 / スキップ: 4件 / 失敗: 0件`となる。既存ユーザーの情報(UID等)が変化しない | F-04, N-01 |
| TC-07 | ドライランモードでの動作確認 | 対象ユーザーが未作成の状態 | `sudo ./create_users.sh -f users.csv -n` を実行する | 画面・ログに`[dry-run]`付きの予定内容が出力されるが、`id yamada_t`を実行すると「そのようなユーザーは存在しません」となり、実際には何も作成されていないことが確認できる | F-08, N-02 |
| TC-08 | ログファイルへの出力内容確認 | 任意のテスト実行後 | `logs/`配下の最新ログファイルを`cat`で確認する | 画面に表示された内容とログファイルの内容が完全に一致する。各行に日時とレベル(INFO/ERROR/SKIP)が付与されている | F-07, N-04 |
| TC-09 | ヘルプ表示 | 特になし(root権限不要) | `./create_users.sh -h` および `./create_users.sh --help` を実行する | どちらも同じ使い方(usage)メッセージが表示され、終了ステータスが`0`である | F-11 |
| TC-10 | 長いオプション(`--dry-run`)の動作確認 | 対象ユーザーが未作成 | `sudo ./create_users.sh -f users.csv --dry-run` を実行する | `-n`指定時と同じ結果になる(実際の変更が行われず、`[dry-run]`ログが出力される) | F-08 |
| TC-11 | ログ出力先ディレクトリの指定(`-l`) | 特になし | `sudo ./create_users.sh -f users.csv -n -l /tmp/test-logs` を実行する | `/tmp/test-logs/`配下にログファイルが作成される(デフォルトの`./logs`ではない) | F-07 |

## 4. 異常系テストケース

| ID | テスト内容 | 前提条件 | 操作手順 | 期待結果 | 関連要件 |
|---|---|---|---|---|---|
| TC-12 | 一般ユーザーでの実行(root権限チェック) | 一般ユーザー(sudoなし)でログイン済み | `./create_users.sh -f users.csv` を`sudo`なしで実行する | `エラー: このスクリプトはroot権限で実行してください。`が標準エラー出力に表示され、処理が開始されずに終了する。終了ステータスが`1` | F-09 |
| TC-13 | 存在しないCSVファイルの指定 | 指定するCSVファイルが存在しない | `sudo ./create_users.sh -f nofile.csv` を実行する | `エラー: CSVファイルが見つかりません: nofile.csv`が表示され、終了ステータスが`1` | F-01 |
| TC-14 | 必須項目が空の行を含むCSV | ユーザー名が空欄の行を含むCSVを用意 | `sudo ./create_users.sh -f bad.csv` を実行する | 該当行のみ`[ERROR] 不正な行のためスキップ: 必須項目が空です`とログに記録され、他の正常行の処理は継続される。終了ステータスが`1`(失敗1件以上のため) | F-10, N-06 |
| TC-15 | 不正な形式のユーザー名を含むCSV | ユーザー名に大文字や`!`など使用不可文字を含む行を用意(例: `Bad-Name!`) | `sudo ./create_users.sh -f bad.csv` を実行する | 該当行が`[ERROR] 不正なユーザー名のためスキップ`として記録され、そのユーザーは作成されない。他の行は正常に処理される | F-10, N-06 |
| TC-16 | 未定義オプションの指定 | 特になし | `./create_users.sh -x` を実行する | `illegal option -- x`とusageメッセージが表示され、終了ステータスが`1` | F-11 |
| TC-17 | CSVファイルの読み取り権限がない場合 | `chmod 000 users.csv`で読み取り不可にしたCSVを用意 | `sudo ./create_users.sh -f users.csv` を実行する | `エラー: CSVファイルの読み取り権限がありません: users.csv`が表示され、終了ステータスが`1` | F-01 |
| TC-18 | CSVがCRLF(Windows形式)改行の場合 | Excel等で保存した際に発生しやすいCRLF改行のCSVを用意 | `sudo ./create_users.sh -f crlf.csv` を実行する | 行末の`\r`がユーザー名等に混入せず、通常のCSVと同じ結果でユーザーが作成される(スクリプト内で`\r`除去処理を行っているため) | F-10 |
| TC-19 | 1行分の処理失敗時の継続動作 | 途中の行でユーザー作成が失敗する状況(例: 直前の行が原因でグループ作成が失敗するような不正データ) | `sudo ./create_users.sh -f bad.csv` を実行する | 失敗した行は`[ERROR]`として記録されつつ、それ以降の正常な行は処理が継続され作成される。スクリプト全体が途中で停止しない | N-06 |
