## Q1. `-bash: ./create_users.sh: Permission denied` と表示されて実行できない

**発生状況**

```bash
$ ./create_users.sh -h
-bash: ./create_users.sh: Permission denied
```

**原因**

スクリプトファイルに実行権限(`x`)が付与されていない。Linuxではファイルの中身がシェルスクリプトでも、実行権限がなければ `./ファイル名` の形では起動できない。

**対処法**

```bash
chmod +x create_users.sh
ls -l create_users.sh
```

```text
-rwxr-xr-x 1 ictadmin ictadmin 9012  4月  1 09:00 create_users.sh
```

`-rwxr-xr-x` のように `x` が含まれていることを確認してから再実行する。詳細は[03-build-guide.md](./03-build-guide.md)の手順4を参照。

## Q2. `エラー: このスクリプトはroot権限で実行してください。` と表示される(sudoを付けたつもり)

**発生状況**

```bash
$ ./create_users.sh -f users.csv
エラー: このスクリプトはroot権限で実行してください。(例: sudo create_users.sh -f users.csv)
```

**原因**

`sudo` を付け忘れている、または `sudo` を付けたコマンド履歴を再実行したときに先頭の `sudo` だけコピーし忘れている、といったケースが多い。本スクリプトは冒頭で `$EUID`(実効ユーザーID)をチェックしており、rootの`0`以外であれば必ずこのエラーになる(要件F-09)。

**対処法**

```bash
sudo ./create_users.sh -f users.csv
```

コマンドの先頭に `sudo` が付いているかを再確認する。それでも解消しない場合は、自分のアカウントに`sudo`権限があるか `sudo -v` で確認する。

## Q3. `エラー: CSVファイルが見つかりません: users.csv` と表示される

**発生状況**

```bash
$ sudo ./create_users.sh -f users.csv
エラー: CSVファイルが見つかりません: users.csv
```

**原因**

CSVファイル自体は存在していても、**スクリプトを実行しているディレクトリ(カレントディレクトリ)と、CSVファイルが置かれているディレクトリが異なる**ことが多い。`-f`にはデフォルトで相対パスが指定されるため、`cd`で移動した先に該当ファイルがないと発生する。

**対処法**

```bash
pwd                 # 今いる場所を確認
ls -l users.csv     # このディレクトリにCSVがあるか確認
```

CSVが別の場所にある場合は、絶対パスで指定するとよい。

```bash
sudo ./create_users.sh -f /opt/account-tool/users.csv
```

## Q4. CSVに書いた氏名が文字化けする(例: `??????` や `譁ュ蟄怜喧縺・`)

**発生状況**

Windows上のExcelで「CSV(カンマ区切り)」形式で保存したファイルをそのままLinuxサーバーに転送すると、ログの氏名欄が文字化けすることがある。

**原因**

Excelの「CSV(カンマ区切り)」形式は、環境によっては文字コードが**Shift_JIS(CP932)**で保存される。一方、本ツール・Linux環境は基本的に**UTF-8**を前提としているため、文字コードの不一致で文字化けする。

**対処法**

`iconv`コマンドで文字コードをUTF-8に変換してから読み込ませる。

```bash
iconv -f SHIFT_JIS -t UTF-8 users_from_excel.csv -o users.csv
```

Excel側で保存する際に「CSV UTF-8(コンマ区切り)」形式を選べる場合は、最初からそちらを使うとこの変換手順を省略できる。

## Q5. Excelで保存したCSVの先頭に変な文字(BOM)が付くと聞いたが、大丈夫か?

**発生状況**

「CSV UTF-8」形式で保存すると、ファイル先頭に目に見えない**BOM(Byte Order Mark = ファイルの先頭に付く文字コード識別用の数バイト)**が付与されることがある、という情報を見て不安になるケース。

**原因・実際の影響**

BOMはファイルの一番先頭、つまり1行目(ヘッダー行)の先頭に付与される。本ツールは `tail -n +2` によって**1行目(ヘッダー行)は常に読み飛ばす**設計になっているため、2行目以降のデータ部分にBOMが混入することはなく、通常は実害がない。

**対処法**

基本的に対処不要。ただし、万一挙動が疑わしい場合は次のコマンドでBOMの有無を確認できる。

```bash
head -c 3 users.csv | od -An -tx1
```

先頭が `ef bb bf` と表示されればBOM付き。心配であれば `sed -i '1s/^\xef\xbb\xbf//' users.csv` で除去できる。

## Q6. `chpasswd` の実行時にパスワード設定が失敗する

**発生状況(例)**

```text
[2026-04-01 09:07:31] [ERROR] ユーザー sato_k のパスワード設定に失敗しました。
```

**原因**

サーバーのパスワードポリシー(PAM の `pam_pwquality` 等)が有効な環境では、辞書に載っている単語や単純すぎる文字列が初期パスワードとして拒否されることがある。これはCSVの中身(パスワード欄)がサーバー側のポリシーを満たしていないことが原因。

**対処法**

- CSVの初期パスワード欄を、大文字・小文字・数字・記号を含む十分な長さの文字列に変更する(例: `ChangeMe123!` のような形式)。
- サーバー側のパスワードポリシーの内容を `cat /etc/security/pwquality.conf` 等で確認し、要件と合わせておく。
- どうしても初期パスワードの自由度を上げたい場合は、情報システム部門内でパスワードポリシーの緩和が妥当かどうかを検討する(セキュリティ低下とのトレードオフのため、安易な緩和は避ける)。

## Q7. ログファイルが作成されず `エラー: ログディレクトリの作成に失敗しました` と表示される

**発生状況**

```bash
$ sudo ./create_users.sh -f users.csv -l /var/log/account-tool
エラー: ログディレクトリの作成に失敗しました: /var/log/account-tool
```

**原因**

`-l` オプションで指定したログ出力先ディレクトリに対して、書き込み権限がない場合に発生する。`sudo`で実行していても、SELinuxやファイルシステムがread-onlyマウントになっている等、OS側の制約で書き込めないケースもある。

**対処法**

```bash
sudo mkdir -p /var/log/account-tool
sudo chmod 750 /var/log/account-tool
```

上記のように事前にディレクトリを作成し、権限を確認してから再実行する。動作確認だけであれば、デフォルトの`./logs`(実行したディレクトリの直下)を使う方がシンプルで問題が起きにくい。
