## 1. どんな場面で必要になるか

毎年4月、株式会社サンプル商事の情報システム部門には「新入社員20名分のLinuxアカウントを作ってほしい」という依頼が届きます。人事から渡されるのは、氏名・ユーザー名・部署・初期パスワードが並んだCSVが1枚だけです。

これを手作業でやると、1人あたり `useradd` `chpasswd` `chage` の3コマンド、20人で60回の入力になります。途中で1文字打ち間違えても気づけませんし、「どこまで作ったか」も分からなくなります。部署のグループを作り忘れて、あとから全員分を直す羽目になった、という事故も珍しくありません。

さらに厄介なのは、**同じ依頼が追加で届く**ことです。「5名追加でお願いします」と言われて同じCSVに5行足して再実行したとき、既に作った15名が二重に作られたりエラーで止まったりしては困ります。何度実行しても結果が変わらない性質を **べき等性 (idempotency)** と呼び、自動化スクリプトで最も大事な性質の1つです。

この演習では、ex01〜ex05で作ってきた部品を1本に組み立てて、案件No.1 `create_users.sh` のミニ版を自分で書きます。ここを越えると「文法の練習」から「実務で動くツール」に景色が変わります。

雛形 `work/mini_create_users.sh` には、このうち **usage関数・log関数・CSVループの枠** を用意してあります。残りを TODO の順に埋めてください。ex01〜ex05で自分が書いた `work/` を開いて、使える部分をどんどん持ってきて構いません。

**新しく出てくるもの1: `$EUID` (実効ユーザーID)**

```bash
if [[ "$EUID" -ne 0 ]]; then
    echo "エラー: このスクリプトはroot権限で実行してください。" >&2
    exit 1
fi
```

`$EUID` はbashが自動的に持っている変数で、いま実行しているユーザーの**実効ユーザーID**が入っています。rootのIDは必ず `0` なので、`0` 以外なら一般ユーザーだと判定できます。`$(id -u)` を使っても同じ判定ができます。

なぜ先に確かめるのかというと、`useradd` はroot以外では必ず失敗するからです。チェックしなければ `Permission denied` が20行並ぶだけの、原因の分かりにくい出力になります。**必要な条件は処理を始める前に自分で確かめ、人間に分かる言葉で伝える**のが良いスクリプトです。

**新しく出てくるもの2: `getent` による存在確認**

```bash
if getent passwd yamada_t > /dev/null 2>&1; then
    echo "yamada_t は既にいる"
fi
```

`getent` (get entries) は、ユーザーやグループの情報を引くコマンドです。見つかれば終了ステータス `0`、見つからなければ `0` 以外を返すので、`if` の条件にそのまま書けます。`/etc/passwd` を `grep` する方法もありますが、`getent` なら社内のLDAPなど外部の管理システムと連携した環境でも正しく判定できるため、実務ではこちらを使います。

`> /dev/null 2>&1` は「標準出力も標準エラー出力も捨てる」という意味です。ここで欲しいのは終了ステータスだけで、ユーザー情報の中身は表示したくないからです。

**新しく出てくるもの3: アカウントを作る4つのコマンド**

| コマンド | 何をするか |
|---|---|
| `groupadd <グループ名>` | グループを作る |
| `useradd -m -c "<氏名>" -g "<部署>" -s /bin/bash <ユーザー名>` | ユーザーを作る。`-m` はホームディレクトリ作成、`-c` は氏名などのコメント、`-g` は所属グループ、`-s` はログインシェル |
| `echo "<ユーザー名>:<パスワード>" \| chpasswd` | 初期パスワードを設定する。パイプで渡すので画面には出ない |
| `chage -d 0 <ユーザー名>` | 最終パスワード変更日を1970-01-01に戻し、初回ログイン時のパスワード変更を強制する |

**新しく出てくるもの4: `=~` による正規表現チェック**

`[[ 文字列 =~ 正規表現 ]]` と書くと、文字列がその正規表現に一致するかを判定できます。`=~` は `[[ ]]` の中でだけ使える演算子です。

```bash
if [[ ! "$username" =~ ^[a-z_][a-z0-9_-]*$ ]]; then
    echo "使えないユーザー名です"
fi
```

この演習で使う `^[a-z_][a-z0-9_-]*$` は、次の部品でできています。

| 部品 | 意味 |
|---|---|
| `^` | 文字列の先頭 |
| `[a-z_]` | 英小文字か `_` のどれか1文字 |
| `[a-z0-9_-]*` | 英小文字・数字・`_`・`-` のどれかが0文字以上続く |
| `$` | 文字列の末尾 |

つまり「英小文字か `_` で始まり、あとは英小文字・数字・`_`・`-` だけ」という意味になります。Linuxのユーザー名はこの形が基本で、`Takahashi.J` のように大文字や `.` を含む名前は `useradd` に弾かれたり、後々のトラブルの原因になったりします。**外から渡された値は、使う前に形を確かめる**のが安全なスクリプトの作法です (正規表現そのものは ex11 でもう一度扱います)。

なお、`=~` の右側の正規表現はクォートで囲みません。`[[ "$username" =~ "^[a-z_]..." ]]` のようにダブルクォートを付けると、正規表現ではなくただの文字列として比較されてしまい、どんな名前も一致しなくなります。

**べき等性 (idempotency) とは**

「同じ操作を何回やっても結果が同じになる」性質のことです。このスクリプトでは2か所で実現します。

- 既にいるユーザーは作らずスキップする (`getent passwd` で確認)
- 既にあるグループは作らない (`getent group` で確認)

こうしておけば、CSVに5行足して再実行しても、増えた5人だけが作られます。ステージ5のAnsibleでは、この考え方そのものが中心テーマになります。

**採点のときはダミーのコマンドが動きます**

採点中、`useradd` `groupadd` `chpasswd` `chage` `getent` は「呼ばれた記録を残すだけの偽物」に差し替えられます。そのため、あなたのPCにユーザーが増えることはありません。ただし差し替えは `PATH` の仕組みを使っているので、**コマンドは `useradd` のように名前だけで書いてください**。`/usr/sbin/useradd` と絶対パスで書くと差し替えが効かず、本物が動いてしまいます。

## 3. 課題

`work/mini_create_users.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 処理の順番

チェックはこの順番で行ってください。採点テストもこの順番を前提にしています。

```text
1. オプションの解析   ( --dry-run / --help を変換してから getopts )
2. -f が指定されているか
3. CSVファイルが存在するか
4. root権限で実行されているか
5. CSVを1行ずつ処理する
6. 集計を表示して終了ステータスを返す
```

引数の書き間違いは誰が実行しても間違いなので、root判定より先に伝えます。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | `-f` を指定せずに実行 | 標準エラー出力に `エラー: -f でCSVファイルを指定してください。` と使い方を表示し、終了ステータス `1` |
| 2 | `-f` に存在しないファイルを指定 | 標準エラー出力に `エラー: CSVファイルが見つかりません: <パス>` を表示し、終了ステータス `1` |
| 3 | `-h` または `--help` を指定 | 使い方を**標準出力**に表示し、終了ステータス `0` |
| 4 | root以外で実行 | 標準エラー出力に `エラー: このスクリプトはroot権限で実行してください。` を表示し、終了ステータス `1`。判定には `$EUID` または `id -u` を使う |
| 5 | CSVの1行目 | ヘッダー行として読み飛ばす |
| 6 | 空行 | 何も出さずに読み飛ばす |
| 7 | ユーザー名が `^[a-z_][a-z0-9_-]*$` に一致しない | `ERROR 不正なユーザー名のためスキップ: <ユーザー名>` を出し、**失敗**件数に数えて次の行へ進む |
| 8 | `getent passwd <ユーザー名>` が成功 (既にいる) | `SKIP ユーザー <ユーザー名> は既に存在するためスキップしました` を出し、**スキップ**件数に数えて次の行へ進む。`useradd` は実行しない |
| 9 | `getent group <部署>` が失敗 (グループが無い) | `groupadd <部署>` で作成し `INFO グループ <部署> を作成しました` を出す。既にあるグループには `groupadd` を実行しない |
| 10 | ユーザーの作成 | `useradd -m -c "<氏名>" -g "<部署>" -s /bin/bash "<ユーザー名>"` を実行し、成功したら `INFO ユーザー <ユーザー名> (氏名: <氏名> / 部署: <部署>) を作成しました` を出して**成功**件数に数える |
| 11 | `useradd` が失敗 | `ERROR ユーザー <ユーザー名> の作成に失敗しました` を出し、**失敗**件数に数えて次の行へ進む (全体は止めない) |
| 12 | 初期パスワードの設定 | `echo "<ユーザー名>:<初期パスワード>" \| chpasswd` を実行する。初期パスワードは画面に表示しない |
| 13 | 初回ログイン時の変更強制 | `chage -d 0 <ユーザー名>` を実行する |
| 14 | `-n` または `--dry-run` を指定 | `groupadd` / `useradd` / `chpasswd` / `chage` を一切実行せず、`INFO [dry-run] ...` の行だけを出す。最後に `ドライランのため、実際には作成していません。` も出す |
| 15 | 最後 | `成功: <件数>件 / スキップ: <件数>件 / 失敗: <件数>件` を表示する |
| 16 | 失敗が1件以上 | 終了ステータス `1`。失敗が0件なら `0` |

### 入力CSVの例

```text
氏名,ユーザー名,部署,初期パスワード
山田 太郎,yamada_t,sales,InitPass01
佐藤 花子,sato_h,sales,InitPass02
鈴木 一郎,suzuki_i,dev,InitPass03
```

### 出力フォーマット

ログの1行は `<レベル> <メッセージ>` の形です。レベルは `INFO` / `SKIP` / `ERROR` の3種類で、レベルとメッセージの区切りは**半角スペース1つ**です。集計行だけはレベルを付けません。

`sales` グループは既にある、`sato_h` は既にいるユーザー、`dev` グループは無い、という状況で実行した場合:

```text
$ sudo ./mini_create_users.sh -f users.csv
INFO CSVファイル: users.csv を読み込みます
INFO ユーザー yamada_t (氏名: 山田 太郎 / 部署: sales) を作成しました
SKIP ユーザー sato_h は既に存在するためスキップしました
INFO グループ dev を作成しました
INFO ユーザー suzuki_i (氏名: 鈴木 一郎 / 部署: dev) を作成しました
成功: 2件 / スキップ: 1件 / 失敗: 0件
```

同じCSVを `-n` (ドライラン) で実行した場合:

```text
$ sudo ./mini_create_users.sh -f users.csv -n
INFO CSVファイル: users.csv を読み込みます
INFO ドライランモードで実行しています。実際の作成は行いません。
INFO [dry-run] ユーザー yamada_t (氏名: 山田 太郎 / 部署: sales) を作成します
SKIP ユーザー sato_h は既に存在するためスキップしました
INFO [dry-run] グループ dev を作成します
INFO [dry-run] ユーザー suzuki_i (氏名: 鈴木 一郎 / 部署: dev) を作成します
成功: 2件 / スキップ: 1件 / 失敗: 0件
ドライランのため、実際には作成していません。
```

不正なユーザー名 `Takahashi.J` が混ざっていた場合 (`dev` グループは既にある状態):

```text
$ sudo ./mini_create_users.sh -f bad_users.csv
INFO CSVファイル: bad_users.csv を読み込みます
ERROR 不正なユーザー名のためスキップ: Takahashi.J
INFO ユーザー tanaka_s (氏名: 田中 三郎 / 部署: dev) を作成しました
成功: 1件 / スキップ: 0件 / 失敗: 1件
$ echo $?
1
```

エラーメッセージは、次の3種類をそのままの文言で標準エラー出力に出します。

```text
エラー: -f でCSVファイルを指定してください。
エラー: CSVファイルが見つかりません: users.csv
エラー: このスクリプトはroot権限で実行してください。
```

## 4. やり方

```bash
# 1. exercises ディレクトリに移動する
cd exercises

# 2. 編集する(エディタは vim でも nano でも VS Code でもよい)
nano ex06-mini-useradd/work/mini_create_users.sh

# 3. 練習用のCSVを作り、まずドライランで動かしてみる
cat > /tmp/users.csv <<'EOF'
氏名,ユーザー名,部署,初期パスワード
山田 太郎,yamada_t,sales,InitPass01
EOF
sudo bash ex06-mini-useradd/work/mini_create_users.sh -f /tmp/users.csv -n

# 4. 採点する
./check.sh 06
```

`./check.sh 06` は一般ユーザーのままでも実行できますが、その場合スクリプト自身がroot権限チェックで止まるため、アカウント作成部分の判定は「スキップ」と表示されます。仕上げには `sudo ./check.sh 06` を実行して、全項目を確認してください。採点中は危険なコマンドがダミーに差し替わるので、`sudo` を付けても実際のアカウントは作られません。

一方、手元で `-n` を外して本番実行すると**本物のユーザーが作られます**。試すときは仮想マシンやコンテナなど、壊れても困らない環境で行ってください。

<details>
<summary>ヒント2: 使う文法の具体例</summary>

**root権限のチェック**

```bash
if [[ "$EUID" -ne 0 ]]; then
    echo "エラー: ..." >&2
    exit 1
fi
```

**存在確認(終了ステータスをそのまま条件に使う)**

```bash
if getent passwd "$username" > /dev/null 2>&1; then
    # 既にいる場合の処理
fi

if ! getent group "$group" > /dev/null 2>&1; then
    # 無い場合の処理(! は「そうでなければ」)
fi
```

**コマンドの失敗を受け止める**

```bash
if ! useradd -m -c "$fullname" -g "$group" -s /bin/bash "$username"; then
    log "ERROR" "ユーザー ${username} の作成に失敗しました"
    FAIL_COUNT=$((FAIL_COUNT + 1))
    continue        # この行は諦めて、次の行へ進む
fi
```

`continue` はループの残りを飛ばして次の行に進む命令です。「1件の失敗で全体を止めない」はこの1語で実現できます。

**カウンタの増やし方**

```bash
SUCCESS_COUNT=$((SUCCESS_COUNT + 1))
```

</details>

<details>
<summary>ヒント3: 1行ぶんの処理の骨組み</summary>

ループの中は、上から順に「関門」を並べていくイメージです。関門に引っかかった行は `continue` で先へ進ませません。

```bash
while IFS=',' read -r fullname username group password || [[ -n "$fullname" ]]; do
    # (CR除去と空行スキップは雛形にあります)

    # 関門1: ユーザー名の形式
    if [[ ! "$username" =~ ^[a-z_][a-z0-9_-]*$ ]]; then
        # ERROR を出して FAIL_COUNT を増やして continue
    fi

    # 関門2: 既にいるユーザーか
    if getent passwd "$username" > /dev/null 2>&1; then
        # SKIP を出して SKIP_COUNT を増やして continue
    fi

    # 関門3: グループが無ければ作る(ドライランなら作らずログだけ)
    if ! getent group "$group" > /dev/null 2>&1; then
        ...
    fi

    # 関門4: ドライランならここで打ち切る
    if [[ "$DRY_RUN" == "true" ]]; then
        # [dry-run] のログを出して SUCCESS_COUNT を増やして continue
    fi

    # ここから先は本番だけが通る「危険地帯」
    # useradd -> chpasswd -> chage -> INFO -> SUCCESS_COUNT

done < <(tail -n +2 "$CSV_FILE")
```

**ドライランの判定を `useradd` の直前に置く**のがポイントです。危険なコマンドに到達させないことが安全装置の本体だからです。

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `成功: 0件 / スキップ: 0件 / 失敗: 0件` としか出ない | `cat file \| while ...` の形で書いている。パイプの右側はサブシェルになり、カウンタがループを抜けると元に戻る。`done < <(tail -n +2 "$CSV_FILE")` の形にする (ex03の復習) |
| `エラー: このスクリプトはroot権限で実行してください。` が出て何も進まない | 仕様どおりの正しい動作。手で試すときは `sudo` を付ける。採点で全項目を判定したいときは `sudo ./check.sh 06` |
| 既にいるはずのユーザーが作られてしまう | `getent passwd "$username"` の終了ステータスを見ていない。`if getent passwd "$username" > /dev/null 2>&1; then` と書く |
| 2回目の実行でエラーが増える | べき等になっていない。既存ユーザー・既存グループの分岐を見直す。ドライランで2回流して、同じ結果になるか確かめる |
| 初期パスワードが画面に出てしまう | `echo "$password"` のように直接表示している。`echo "${username}:${password}" \| chpasswd` とパイプで渡せば表示されない |
| `-n` を付けたのにユーザーが作られた | ドライランの判定が `useradd` より後ろにある、または `continue` を書き忘れている |
| `useradd: command not found` | 一般ユーザーの `PATH` に `/usr/sbin` が無い。`sudo` を付けて実行する (採点時はダミーに差し替わるため影響しません) |

`./check.sh 06` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。
