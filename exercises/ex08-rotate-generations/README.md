## 1. どんな場面で必要になるか

[ex07](../ex07-tar-archive/README.md) で毎晩バックアップを作れるようになりました。ところが、作りっぱなしにすると保存先のディスクは必ず溢れます。溢れた瞬間に何が起きるかというと、**バックアップだけでなく、同じディスクを使っている本番サービスまで止まります**。「バックアップを入れたせいでサービスが落ちた」は、運用でいちばん避けたい事故のひとつです。

そこで必要になるのが**世代管理**です。世代管理とは「直近N回分だけ残して、それより古いものは自動で消す」という運用のことです。ここでの N を「世代数」と呼びます。

世代管理のスクリプトは「自動でファイルを削除する」ため、書き方を間違えると被害が大きくなります。ワイルドカードの指定を1文字間違えただけで、消してはいけない設定ファイルまで巻き込むことがあります。この演習では、案件No.2の `backup.sh` が行っている古い世代の削除を、**削除対象を厳しく絞り込む**書き方と、**本番前に確認するドライラン**の2つを軸に組み立てます。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |

| `getopts` | `-d` `-g` `-n` `-h` のようなオプションを解析する bash の組み込みコマンド |

### 3分でわかる予備知識

**なぜ `ls -t` を使ってはいけないのか**

「更新日時の新しい順に並べる」と聞いて、まず思いつくのが `ls -t` です。実際、対話的に確認するときは便利です。しかし、その結果をスクリプトで受け取るのは危険です。

```bash
# 危険な書き方(まねしないでください)
for f in $(ls -t *.tar.gz); do ...; done
```

`ls` の出力は「人間が読むための表示」であって、機械が読むためのデータ形式ではありません。ファイル名に空白が含まれていると、`my backup.tar.gz` が `my` と `backup.tar.gz` の**2つ**として分割されてしまいます。改行を含むファイル名なら、もっとひどいことになります。削除スクリプトでこれが起きると、存在しない名前を消そうとしたり、意図しないファイルを消したりします。

**安全な並べ替え: `find -printf` + `sort`**

そこで、`find` に「更新日時」と「パス」を自分で並べて出力させます。

```bash
find backup -maxdepth 1 -type f -name 'backup_*.tar.gz' -printf '%T@\t%p\n' | sort -rn | cut -f2-
```

分解すると次のようになります。

| 部分 | 意味 |
|---|---|
| `-maxdepth 1` | 指定したディレクトリの直下だけを見る(サブディレクトリまで潜らない) |
| `-type f` | 通常ファイルだけを対象にする(ディレクトリを除外する) |
| `-name 'backup_*.tar.gz'` | ファイル名で絞り込む。**これが誤削除を防ぐ最重要の1行** |
| `-printf '%T@\t%p\n'` | 「更新日時(エポック秒)<タブ>パス」の形式で出力する |
| `sort -rn` | 数値として(`-n`)逆順に(`-r`)並べる。つまり新しい順になる |
| `cut -f2-` | タブ区切りの2列目以降、つまりパスだけを取り出す |

`%T@` は「1970年1月1日からの経過秒数」で表した更新日時です。数値なので `sort -n` で正しく並びます。日付の文字列で並べ替えようとすると書式によって順序が狂うため、数値で比べるのが確実です。

結果を配列に受け取るには `mapfile` を使います。

```bash
mapfile -t FILES < <(find ... | sort -rn | cut -f2-)
echo "${#FILES[@]}"   # 件数
echo "${FILES[0]}"    # いちばん新しいファイル
```

`mapfile -t` は「1行を1要素として配列に読み込む(`-t` は行末の改行を捨てる)」コマンドです。`< <(...)` は**プロセス置換**という書き方で、コマンドの出力をファイルのように読み込ませます。

**ドライランという習慣**

削除や再起動のように「取り返しがつかない操作」をするスクリプトには、必ず**ドライラン**(実行したふりをして、何が起きるかだけ表示するモード)を用意します。本番のサーバーでは、まずドライランで対象を目視確認し、納得してから本実行する、というのが基本の手順です。

```bash
if [[ "$DRY_RUN" == "true" ]]; then
    echo "[dry-run] 削除します: ${name}"
else
    rm -f -- "$file"
    echo "削除しました: ${name}"
fi
```

**数値かどうかを確かめる**

`-g abc` のように指定された値をそのまま比較に使うと、意味の分からないエラーで止まります。使う前に形を確かめます。

```bash
if [[ ! "$GENERATIONS" =~ ^[0-9]+$ ]]; then
    echo "エラー: 世代数には数値を指定してください" >&2
    exit 1
fi
```

`=~` は正規表現との照合です。`^[0-9]+$` は「先頭から末尾まで、数字が1文字以上だけ」という意味になります。正規表現はクォートで囲まないのがポイントです(囲むとただの文字列として比較されてしまいます)。

## 3. 課題

`work/rotate_backups.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 基本の使い方 | `rotate_backups.sh -d <保存ディレクトリ> [-g <残す世代数>] [-n] [-h]` |
| 2 | `-g` を省略した | 残す世代数は既定値の **3** とする |
| 3 | `-n` または `--dry-run` | 実際には削除せず、削除対象を表示するだけにする |
| 4 | `-h` または `--help` | 使い方を**標準出力**に表示し、終了ステータス `0` |
| 5 | `-d` を指定しなかった | `エラー: -d でバックアップ保存ディレクトリを指定してください` を**標準エラー出力**に表示し、終了ステータス `1` |
| 6 | `-d` のディレクトリが存在しない | `エラー: ディレクトリが見つかりません: <パス>` を**標準エラー出力**に表示し、終了ステータス `1` |
| 7 | `-g` の値が数値でない | `エラー: 世代数には数値を指定してください` を**標準エラー出力**に表示し、終了ステータス `1` |
| 8 | 削除の対象 | `backup_*.tar.gz` に一致するファイル**だけ**。それ以外は絶対に削除しない |
| 9 | 残すもの | 更新日時が新しいものから世代数ぶん。それより古いものを削除する |
| 10 | 削除したとき | 1件ごとに `削除しました: <ファイル名>` を標準出力に表示する |
| 11 | ドライランのとき | 1件ごとに `[dry-run] 削除します: <ファイル名>` を標準出力に表示する |
| 12 | 最後に必ず | `保持: <件数>件 / 削除: <件数>件` を標準出力に表示する |
| 13 | 対象が世代数以下しかない | 何も削除せず、終了ステータス `0` で終わる |

- `<ファイル名>` はパスを含まない**ファイル名だけ**です。`basename` で取り出してください
- ドライランのときも「削除するはずだった件数」を `削除:` に数えます
- 世代数が `0` の場合は、対象すべてが削除対象になります

### 実行例

保存ディレクトリの中身が次の状態だとします。

```text
backup/
├── backup_20260901_010000.tar.gz   ← 最も古い
├── backup_20260902_010000.tar.gz
├── backup_20260903_010000.tar.gz
├── backup_20260904_010000.tar.gz
├── backup_20260905_010000.tar.gz   ← 最も新しい
├── keepme.txt                       ← パターン外。消してはいけない
└── other.tar.gz                     ← パターン外。消してはいけない
```

まずドライランで確認します。

```text
$ bash rotate_backups.sh -d backup -n
[dry-run] 削除します: backup_20260902_010000.tar.gz
[dry-run] 削除します: backup_20260901_010000.tar.gz
保持: 3件 / 削除: 2件
```

問題なければ本実行します。

```text
$ bash rotate_backups.sh -d backup -g 3
削除しました: backup_20260902_010000.tar.gz
削除しました: backup_20260901_010000.tar.gz
保持: 3件 / 削除: 2件
```

対象が世代数以下しかない場合は、何も削除しません。

```text
$ bash rotate_backups.sh -d backup -g 3
保持: 2件 / 削除: 0件
```

### 出力フォーマット

行の書式は次のとおりです。**コロン・半角スペース・スラッシュの位置まで**合わせてください。削除する順番(新しい順・古い順)は採点しません。

```text
削除しました: backup_20260901_010000.tar.gz
[dry-run] 削除します: backup_20260901_010000.tar.gz
保持: 3件 / 削除: 2件
```

- `保持:` の後ろは半角スペース、件数、`件`、半角スペース、`/`、半角スペース、`削除:` と続きます

エラーメッセージの書式は次のとおりです。

```text
エラー: -d でバックアップ保存ディレクトリを指定してください
エラー: ディレクトリが見つかりません: nosuchdir
エラー: 世代数には数値を指定してください
```

## 4. やり方

```bash
# 1. exercises ディレクトリに移動する
cd exercises

# 2. 編集する(エディタは vim でも nano でも VS Code でもよい)
nano ex08-rotate-generations/work/rotate_backups.sh

# 3. 練習用のバックアップを作って動かしてみる
mkdir -p /tmp/ex08/backup
for d in 01 02 03 04 05; do
    : > "/tmp/ex08/backup/backup_202609${d}_010000.tar.gz"
    touch -t "202609${d}0100" "/tmp/ex08/backup/backup_202609${d}_010000.tar.gz"
done
: > /tmp/ex08/backup/keepme.txt
bash ex08-rotate-generations/work/rotate_backups.sh -d /tmp/ex08/backup -n   # まずドライラン
bash ex08-rotate-generations/work/rotate_backups.sh -d /tmp/ex08/backup      # 本実行
ls -l /tmp/ex08/backup

# 4. 採点する
./check.sh 08
```

`touch -t YYYYMMDDhhmm <ファイル>` は、ファイルの更新日時を指定した日時に書き換えるコマンドです。世代管理の動作確認では、このように**日時を意図的にずらしたテスト用ファイル**を用意します。

採点に合格すると、次のように表示されます。

```text
  ✓ [1] bashの構文エラーがない
  ✓ [2] -d を指定しないと終了ステータス1で終わる
  ...
  結果: 16/16 合格
```

## 5. ヒント

自力で20分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: どういう順番で処理を組み立てるか</summary>

削除するスクリプトは「消す前に、確認できることを全部確認する」順番で書きます。

1. 既定値を変数に入れておく(世代数 3、ドライランは false)
2. `--dry-run` `--help` を `-n` `-h` に置き換える(ex05 と同じ手法)
3. `getopts` でオプションを読み取る
4. `-d` が指定されているか、そのディレクトリが存在するかを確かめる
5. 世代数が数値かどうかを確かめる
6. `backup_*.tar.gz` を新しい順に並べた一覧を作る
7. 一覧を先頭から見て、世代数までは残す、それ以降は削除する
8. 最後に件数を表示する

4と5を先に済ませてしまえば、あとの処理では「値は正しい」と信じて書けます。**入力の検証を最初にまとめる**のは、読みやすさと安全性の両方に効きます。

</details>

<details>
<summary>ヒント2: 使う文法の具体例</summary>

**オプションの解析**

```bash
while getopts "d:g:nh" opt; do
    case "$opt" in
        d)  BACKUP_DIR="$OPTARG" ;;
        g)  GENERATIONS="$OPTARG" ;;
        n)  DRY_RUN="true" ;;
        h)  usage; exit 0 ;;
        \?) usage >&2; exit 1 ;;
    esac
done
shift $((OPTIND - 1))
```

`d:` の `:` は「このオプションは値を取る」という印で、値は `$OPTARG` に入ります。`-n` と `-h` は値を取らないので `:` を付けません。

**新しい順の一覧を配列に取る**

```bash
mapfile -t FILES < <(
    find "$BACKUP_DIR" -maxdepth 1 -type f -name 'backup_*.tar.gz' -printf '%T@\t%p\n' \
        | sort -rn \
        | cut -f2-
)
```

**先頭から数えて残す・消すを決める**

```bash
INDEX=0
for file in "${FILES[@]}"; do
    INDEX=$((INDEX + 1))
    if [[ "$INDEX" -le "$GENERATIONS" ]]; then
        # 新しい側なので残す
        continue
    fi
    # ここに来たものが削除対象
done
```

配列は新しい順に並んでいるので、「先頭から数えて世代数以内なら残す」だけで世代管理になります。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

BACKUP_DIR=""
GENERATIONS=3
DRY_RUN="false"

usage() { ... }

# --dry-run / --help を -n / -h に変換してから getopts に渡す(ex05 と同じ)

while getopts "d:g:nh" opt; do ... done
shift $((OPTIND - 1))

# -d の未指定チェック → ディレクトリの存在チェック → 世代数の数値チェック

mapfile -t FILES < <(find ... | sort -rn | cut -f2-)

KEPT=0
DELETED=0
INDEX=0
for file in "${FILES[@]}"; do
    INDEX=$((INDEX + 1))
    name="$(basename "$file")"
    if [[ "$INDEX" -le "$GENERATIONS" ]]; then
        KEPT=$((KEPT + 1))
        continue
    fi
    if [[ "$DRY_RUN" == "true" ]]; then
        echo "[dry-run] 削除します: ${name}"
    else
        rm -f -- "$file"
        echo "削除しました: ${name}"
    fi
    DELETED=$((DELETED + 1))
done

echo "保持: ${KEPT}件 / 削除: ${DELETED}件"
exit 0
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `keepme.txt` まで消えてしまう | `find` の `-name` を付け忘れているか `*` だけにしている。`-name 'backup_*.tar.gz'` で必ず絞り込む |
| 新しいバックアップのほうが消える | `sort` の向きが逆。`sort -rn` は新しい順、`sort -n` は古い順になる |
| `bash: [: 3: 単項演算子が予期されます` と出る | `-g` の値が空、または `$GENERATIONS` のクォート漏れ。`[[ "$INDEX" -le "$GENERATIONS" ]]` のように囲む |
| `保持: 0件 / 削除: 0件` としか出ない | `find` のパスやパターンが合っていない。まず `find ... -printf '%T@\t%p\n'` だけを手で実行して結果を見る |
| `-n` を付けたのにファイルが消えた | `rm` が `if` の外に出ている。ドライランの分岐の中に `rm` が入らないよう構造を見直す |
| `-g` に文字を渡すと変なエラーで止まる | 数値チェックをしていない。`[[ ! "$GENERATIONS" =~ ^[0-9]+$ ]]` で先に弾く |

`./check.sh 08` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。

1. ファイル名に空白や改行が含まれていても壊れないよう、`-printf '%T@\t%p\0'` と `sort -zrn`、`mapfile -d ''` を使った NUL 区切りの実装に書き換える
2. 削除の代わりに `-a <退避先>` で別ディレクトリへ移動する「アーカイブモード」を追加する
3. 削除した内容を `rotate.log` に日時つきで追記する(ex04 で書いたログ関数を持ち込む)
