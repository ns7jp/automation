## 1. どんな場面で必要になるか

株式会社サンプル商事では、毎月の入社者リストが人事部から「氏名,ユーザー名,部署,初期パスワード」の4列のCSVで届きます。情報システム部の担当者は、この1行ぶんが1人ぶんのアカウントに対応するので、**ファイルを上から1行ずつ取り出して、同じ処理を人数分くり返す**ことになります。

ところが、人が手作業で作ったCSVはきれいではありません。WindowsのExcelで保存されているので行末に見えない文字が付いていたり、最後の行の改行が抜けていたり、途中に空行が入っていたり、ユーザー名の欄だけ空だったりします。**この「汚れたCSV」を前提にしないスクリプトは、本番でほぼ必ず落ちます。**

そして、こうした行を見つけたときに処理全体を止めてしまうのも困ります。40人ぶんのうち1行が不正だっただけで、残りの39人が作られないからです。正しい振る舞いは「その行だけスキップして記録を残し、次の行へ進む」ことです。

この演習では、アカウントを作る処理はまだ書きません。**CSVを正しく読み分ける部分だけ**を取り出して練習します。ここは案件No.1 `create_users.sh` の心臓部そのものです。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| `while read` ループ | ファイルを1行ずつ読み込む定番の形。行が無くなると自動的に終わる |
| `IFS=','` | 区切り文字の指定。カンマ区切りの1行を、複数の変数に一度に振り分けられる |
| `read -r` | バックスラッシュを特別扱いしない指定。`read` には常に `-r` を付ける |
| パラメータ展開 `${var%...}` | 変数の末尾から余計な文字を取り除く。行末のCR除去に使う |
| プロセス置換 `< <(...)` | パイプの代わりに使う書き方。ループ内で数えた件数がループの外でも生き残る |
| `continue` | 残りの処理を飛ばして次の行へ進む。「この行はスキップ」を表す |

### 3分でわかる予備知識

**1行ずつ読む基本形**

```bash
while read -r line; do
    echo "読んだ行: ${line}"
done < users.csv
```

`done` の後ろの `< users.csv` が「このループにこのファイルを流し込む」という指定です。`read` は1回呼ばれるごとに1行読み、読む行が無くなると失敗を返すので、そこでループが終わります。

**カンマで区切って複数の変数に入れる**

`IFS` は Internal Field Separator の略で、「単語の区切り文字」を意味する特別な変数です。既定値は空白とタブと改行ですが、`read` の直前に `IFS=','` と書くと、その `read` の間だけ区切り文字がカンマになります。

```bash
while IFS=',' read -r fullname username dept password; do
    echo "${fullname} さんのユーザー名は ${username} です"
done < users.csv
```

`佐藤 花子,sato_h,eigyou,Passw0rd!` という行なら、`fullname="佐藤 花子"`、`username="sato_h"`、`dept="eigyou"`、`password="Passw0rd!"` になります。氏名に空白が含まれていても、区切りはカンマだけなので分割されません。

**ヘッダー行を読み飛ばす**

1行目は列名なので処理してはいけません。`tail -n +2` は「2行目以降だけを出力する」コマンドです。

```bash
tail -n +2 users.csv     # 2行目から最後まで
```

`-n +2` の `+` を忘れて `tail -n 2` と書くと「最後の2行」という全く別の意味になります。

**落とし穴1: Windowsで保存したCSVには見えない文字が付く**

Windowsの改行は CR(復帰)と LF(改行)の2文字、Linuxの改行は LF の1文字です。Windowsで保存されたCSVをそのまま読むと、**行の最後の項目に CR が1文字くっついたまま**になります。

```bash
$ od -c users.csv | head -2
0000000   氏  名   ,   ユ  ー  ザ  ー  名   ...  ワ  ー  ド  \r  \n
                                                          ^^^^ これが CR
```

見た目では分からないのに、`[[ -z "$password" ]]`(空かどうか)の判定が期待どおりに動かなくなります。空のはずの項目が「CRという1文字が入っている」ことになるからです。取り除くにはパラメータ展開を使います。

```bash
password="${password%$'\r'}"
```

`${変数%パターン}` は「末尾がパターンに一致するなら、その部分を取り除く」という書き方です。`$'\r'` は「CRという1文字」を表すbash独自の書き方です。末尾にCRが無ければ何も起こらないので、Linuxで作ったCSVに対して実行しても安全です。

**落とし穴2: 最終行に改行が無いと最後の1行が消える**

`read` は「改行を見つけるまで読む」コマンドなので、ファイルの最後に改行が無いと、最後の行を変数に入れたうえで「失敗」を返します。`while` はその失敗を見てループを終わらせるため、**最後の1行だけが処理されません。** 定番の対策はこの形です。

```bash
while IFS=',' read -r fullname username dept password || [[ -n "$fullname" ]]; do
```

「read が成功したか、**または** 1つ目の変数に中身が残っているなら」ループを続ける、という意味です。

**落とし穴3: パイプで渡すと件数が消える(最重要)**

次の2つは、似ているようで結果が違います。

```bash
# 悪い例: 最後に必ず「合計: 0件」と出てしまう
COUNT=0
tail -n +2 users.csv | while IFS=',' read -r a b c d; do
    COUNT=$((COUNT + 1))
done
echo "合計: ${COUNT}件"
```

```bash
# 良い例: 数えた結果がループの外でも生きている
COUNT=0
while IFS=',' read -r a b c d; do
    COUNT=$((COUNT + 1))
done < <(tail -n +2 users.csv)
echo "合計: ${COUNT}件"
```

パイプ `|` の右側は**サブシェル**(子プロセスとして起動される別のシェル)で実行されます。子プロセスで変数を書き換えても、親には伝わりません。ループを抜けた瞬間に、数えた結果が消えてしまうわけです。

`< <(コマンド)` は**プロセス置換**という書き方で、「コマンドの出力を、あたかもファイルであるかのようにループへ流し込む」ものです。こちらはループ本体が親シェルで動くので、カウンタが生き残ります。`<` と `<(` の間には**半角スペースが必要**です。

**`continue` で次の行へ進む**

```bash
if [[ -z "$username" ]]; then
    echo "スキップします"
    continue        # これ以降の処理を飛ばして、次の行の読み込みへ
fi
```

## 3. 課題

`work/parse_users.sh` を編集し、ユーザー一覧のCSVを1行ずつ読んで一覧表示するスクリプトを完成させてください。CSVの列は `氏名,ユーザー名,部署,初期パスワード` の4列固定です。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 引数がちょうど1個ではない | 「使い方」を含むメッセージを**標準エラー出力**に表示し、終了ステータス `1` |
| 2 | 指定されたCSVファイルが存在しない | 標準エラー出力に `エラー: ファイルが見つかりません: <パス>` を表示し、終了ステータス `1` |
| 3 | 1行目(ヘッダー行) | 読み飛ばす。何も表示しない |
| 4 | 空行 | 何も表示せずに読み飛ばす。件数にも数えない |
| 5 | 4項目のどれかが空の行 | 標準出力に `スキップ: <行番号>行目 項目が足りません` を表示し、スキップ件数に1を足す |
| 6 | 4項目がそろっている行 | 標準出力に `[<連番>] <氏名> / <ユーザー名> / <部署>` を表示し、正常件数に1を足す |
| 7 | すべての行を処理し終えたあと | 標準出力に `合計: <正常件数>件 (スキップ: <スキップ件数>件)` を表示し、終了ステータス `0` |
| 8 | 行末に CR が付いたCSV(Windows保存) | CRを取り除いてから判定・表示する |
| 9 | 最終行に改行が無いCSV | 最後の1行も落とさずに処理する |
| 10 | 初期パスワード | **絶対に画面に出さない**(項目が空かどうかの判定にだけ使う) |

- `<行番号>` は **ヘッダー行を1行目として数えた、ファイル内の実際の行番号**です。空行も1行として数えます
- `<連番>` は正常に処理できた行の通し番号で、`1` から始まります
- 行の表示は `[1] 佐藤 花子 / sato_h / eigyou` のように、区切りを **半角スペース+半角スラッシュ+半角スペース** にします

### 実行例 / 出力フォーマット

次の `users.csv` を用意したとします(2行目と4行目の行末はCR+LF、6行目は改行なしで終わっている)。

```text
1: 氏名,ユーザー名,部署,初期パスワード
2: 佐藤 花子,sato_h,eigyou,Passw0rd!
3:
4: 田中 太郎,tanaka_t,soumu,
5: 鈴木 一郎,suzuki_i,kaihatsu,Pw12345
6: 山田 次郎,yamada_j,jinji,TopSecret9
```

このときの実行結果は次のとおりです。

```text
$ bash parse_users.sh users.csv
[1] 佐藤 花子 / sato_h / eigyou
スキップ: 4行目 項目が足りません
[2] 鈴木 一郎 / suzuki_i / kaihatsu
[3] 山田 次郎 / yamada_j / jinji
合計: 3件 (スキップ: 1件)
$ echo $?
0
```

- 3行目の空行は何も表示されない
- 4行目は初期パスワードが空(行末のCRを取り除くと空になる)なので、スキップとして記録する
- 6行目は改行で終わっていないが、落とさずに処理する
- ヘッダー行が処理されていないので `[1]` は佐藤さんになる

データが1件も無い場合(ヘッダー行だけのCSV)も、エラーにはせずに次のように終わります。

```text
$ bash parse_users.sh header_only.csv
合計: 0件 (スキップ: 0件)
$ echo $?
0
```

## 5. ヒント

自力で20分考えてから開いてください。

<details>
<summary>ヒント1: 処理の流れを日本語で整理する</summary>

1行ぶんの処理は、必ず**手前で弾ける条件から順に**書きます。

```text
[準備] 正常件数 = 0 / スキップ件数 = 0 / 行番号 = 1 (ヘッダーぶん)

くり返し: 2行目以降を1行ずつ読む
    行番号を1増やす            ← 先に増やすことで「今読んでいる行の番号」になる
    4つの変数から行末のCRを取り除く
    4つとも空か?              → 空行なので、何も出さずに次の行へ (continue)
    1つでも空があるか?         → スキップのメッセージを出し、スキップ件数+1、次の行へ
    ここまで来たら正常な行
        正常件数を1増やす
        [連番] 氏名 / ユーザー名 / 部署 を表示する

[最後] 合計行を表示して exit 0
```

行番号の初期値が `1` なのは、`tail -n +2` でヘッダー行を読み飛ばしているためです。ループの先頭で1を足すので、最初のデータ行はちょうど `2` になります。

</details>

<details>
<summary>ヒント2: 使う文法の具体例</summary>

CR の除去は4つの変数それぞれに対して行います。

```bash
fullname="${fullname%$'\r'}"
```

「4つとも空」と「1つでも空」は、`&&`(かつ)と `||`(または)で書き分けます。

```bash
if [[ -z "$fullname" && -z "$username" && -z "$dept" && -z "$password" ]]; then
    continue          # 空行
fi

if [[ -z "$fullname" || -z "$username" || -z "$dept" || -z "$password" ]]; then
    echo "スキップ: ${LINE_NO}行目 項目が足りません"
    SKIP_COUNT=$((SKIP_COUNT + 1))
    continue
fi
```

数を1増やす書き方は `COUNT=$((COUNT + 1))` です。`$(( ))` の中では変数に `$` を付けなくても構いません。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

# ここに引数チェックとファイル存在チェック(ex02の復習)

CSV_FILE="$1"

OK_COUNT=0
SKIP_COUNT=0
LINE_NO=1                 # 1行目はヘッダー行

while IFS=',' read -r fullname username dept password || [[ -n "$fullname" ]]; do
    LINE_NO=$((LINE_NO + 1))

    # ここで4つの変数から行末のCRを取り除く

    # ここで空行の判定 (continue)

    # ここで項目不足の判定 (メッセージ + SKIP_COUNT + continue)

    # ここまで来たら正常な行
    OK_COUNT=$((OK_COUNT + 1))
    echo "[${OK_COUNT}] ..."
done < <(tail -n +2 "$CSV_FILE")

echo "合計: ..."
exit 0
```

`done < <(tail -n +2 "$CSV_FILE")` の形を必ず使ってください。`tail ... | while ...` と書くと、最後の合計が必ず `0件` になります(予備知識の落とし穴3)。

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `合計: 0件 (スキップ: 0件)` としか出ない | `tail ... \| while ...` とパイプで渡している。`done < <(tail -n +2 "$CSV_FILE")` の形に直す |
| `syntax error near unexpected token '('` | プロセス置換の `<` と `<(` の間に半角スペースが無い。`< <(` と書く |
| 1行目の「氏名 / ユーザー名 / 部署」が表示される | ヘッダーを読み飛ばしていない。`tail -n +2` を使う |
| 最後の1人が表示されない | 最終行に改行が無いCSV。`while ... read ... \|\| [[ -n "$fullname" ]]; do` の形にする |
| 項目が空なのにスキップされない | 行末のCRが残っている。4つの変数すべてに `${var%$'\r'}` を適用する |
| 行番号が1つずれる | `LINE_NO` の初期値は `1`(ヘッダー行ぶん)。ループの**先頭**で1を足す |
| `unbound variable` と出る | `set -u` を付けた状態で `$1` を参照している。引数チェックを先に済ませてから代入する |

## 7. 発展課題(採点対象外)

1. 列数が4より多い行(カンマが5個以上ある行)を検出し、`スキップ: <行番号>行目 列が多すぎます` と表示する
2. ユーザー名が重複している行を検出してスキップする(連想配列 `declare -A seen` を使う)
3. `-q` オプションを付けたときは1行ごとの表示を省略し、合計行だけを出す

## 8. この演習と案件のつながり

案件No.1 `create_users.sh` の「9. CSVを1行ずつ読み込んで処理する」は、この演習で書いたループそのものです。

- `while IFS=',' read -r fullname username group password || [[ -n "$fullname" ]]` → [`create_users.sh`](../../projects/01-user-account-automation/src/create_users.sh) のCSV読み込みループ
- 行末CRの除去(`${fullname%$'\r'}`)→ 同ループ冒頭の「行末の\r除去」
- 空行スキップ・必須項目チェック・`continue` → 同ループの「空行はスキップ」「必須項目チェック」
- `done < <(tail -n +2 "$CSV_FILE")` と件数カウンタ → 同ループの末尾と「10. 処理結果サマリの出力」

案件本体では、この演習で `echo` している場所が `useradd` や `chpasswd` の呼び出しに置き換わります。**表示するだけなら安全ですが、そこにアカウント作成が入ると1行の判定ミスが事故になります。** だからこそ、読み分けの部分だけを先に完璧にしておく価値があります。
