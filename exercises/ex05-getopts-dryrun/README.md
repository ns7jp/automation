## 1. どんな場面で必要になるか

「一時ファイルが溜まってディスクが満杯になり、深夜にサービスが止まった」というのは、運用の現場でよくある障害です。対策として、古い一時ファイルを消す掃除スクリプトを定期実行することになります。

ところが、削除するスクリプトは**一番事故が起きやすいスクリプト**でもあります。対象ディレクトリを1文字打ち間違えただけで、消してはいけないファイルを消してしまいます。そして削除は取り消せません。

そこで実務では、削除系のスクリプトに必ず**ドライラン(dry-run)** を用意します。「本当に実行したら何が起きるか」を表示するだけで、実際には何も変更しないモードのことです。運用手順書も「まず `-n` を付けて対象を確認し、問題なければ `-n` を外して実行する」という書き方になります。

この演習では、`-d` `-e` `-n` `-h` の4つのオプションを持つ掃除ツールを作ります。案件No.1の `create_users.sh` も、まったく同じ形でオプションを解析し、`--dry-run` を実装しています。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| `getopts` | `-d ./tmp` のような「短いオプション」を解析するbash組み込みの仕組み |
| `OPTARG` / `OPTIND` | オプションに渡された値 / 次に読む引数の位置。getopts が自動で設定する |
| 長いオプションの変換 | `--dry-run` を `-n` に置き換えてから getopts に渡すという定番の手法 |
| 既定値 | オプション指定が無いときに使う値。変数の初期値として先に入れておく |
| ドライラン | 実際には変更せず、実行内容だけを表示する安全モード |
| グロブ(`*.tmp`) | ファイル名のパターン展開。**1件もマッチしないときの挙動に注意が必要** |

### 3分でわかる予備知識

**getopts の基本形**

```bash
DIR="./tmp"          # 先に既定値を入れておく
DRY_RUN="false"

while getopts "d:nh" opt; do     # d の後ろの : は「このオプションは値を取る」印
    case "$opt" in
        d)  DIR="$OPTARG" ;;     # -d に渡された値は $OPTARG に入る
        n)  DRY_RUN="true" ;;    # 値を取らないオプションは有無だけを見る
        h)  usage; exit 0 ;;
        \?) usage >&2; exit 1 ;; # 未定義のオプションが来ると opt は ? になる
    esac
done
shift $((OPTIND - 1))            # 処理したオプションの分だけ引数をずらす
```

- `"d:nh"` は「`-d` は値あり、`-n` と `-h` は値なし」という意味です
- `case` のパターンに `?` をそのまま書くと「任意の1文字」というワイルドカードになってしまうため、`\?` とエスケープします
- `shift $((OPTIND - 1))` は、オプションの後ろに書かれたファイル名などを `$1` で受け取るための決まり文句です。今回は使いませんが、書く習慣を付けてください

**長いオプション(`--dry-run`)の扱い方**

`getopts` は仕様上、`-n` のような1文字のオプションしか扱えません。`--dry-run` も使えるようにするには、**getopts に渡す前に短いオプションへ置き換えてしまう**のが一般的な手法です。

```bash
args=()
for arg in "$@"; do
    case "$arg" in
        --dry-run) args+=("-n") ;;   # --dry-run を -n に置き換える
        --help)    args+=("-h") ;;
        *)         args+=("$arg") ;; # それ以外はそのまま
    esac
done
set -- "${args[@]}"     # 置き換えた結果で $1, $2, ... を丸ごと入れ替える
```

`args+=("$arg")` は配列(値を順番に入れておける箱)の末尾に追加する書き方です。`set -- ...` は「位置引数($1 以降)を指定した内容で置き換える」コマンドです。

**グロブがマッチしないときの落とし穴**

```bash
for file in ./tmp/*.tmp; do
    echo "$file"
done
```

対象が1件も無いとき、bashは既定では**パターン文字列そのもの**(`./tmp/*.tmp`)を1回返します。何も表示されないわけではありません。そのまま数えると「対象: 1件」と表示され、`rm` に渡せば「そんなファイルはない」というエラーになります。

そこで、ループの先頭に存在チェックを入れます。

```bash
for file in ./tmp/*.tmp; do
    [[ -f "$file" ]] || continue    # 実在する通常ファイル以外は飛ばす
    ...
done
```

`[[ -f "$file" ]] || continue` は「ファイルとして存在しなければ、次の繰り返しへ飛ぶ」という意味です。これで、マッチが0件のときもディレクトリが混ざったときも安全になります。

**basename でファイル名だけ取り出す**

```bash
basename ./tmp/a.tmp     # → a.tmp
```

ループで受け取る `$file` には `./tmp/a.tmp` のようにパスが付いています。表示用にファイル名だけが欲しいときは `basename` を使います。

## 3. 課題

`work/cleanup_tool.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 使い方

```text
cleanup_tool.sh [-d <ディレクトリ>] [-e <拡張子>] [-n] [-h]
```

| オプション | 意味 | 既定値 |
|---|---|---|
| `-d <ディレクトリ>` | 掃除する対象ディレクトリ | `./tmp` |
| `-e <拡張子>` | 削除する拡張子。**ドットは付けずに** `tmp` `log` のように指定する | `tmp` |
| `-n` | ドライラン。1件も削除せず、削除予定だけを表示する。`--dry-run` も同じ意味 | なし |
| `-h` | 使い方を表示して終了する。`--help` も同じ意味 | なし |

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | オプションなしで実行 | `./tmp` の中の `*.tmp` を削除する |
| 2 | `-d` / `-e` を指定 | 対象ディレクトリ / 拡張子を変える |
| 3 | `-h` または `--help` | 使い方を**標準出力**に表示し、終了ステータス `0` |
| 4 | 未定義のオプション(例: `-z`) | 使い方を**標準エラー出力**に表示し、終了ステータス `1` |
| 5 | 対象ディレクトリが存在しない | 標準エラー出力に `エラー: ディレクトリが見つかりません: <パス>` を出し、終了ステータス `1` |
| 6 | 削除できた(本番実行) | 1件ごとに `削除しました: <ファイル名>` を標準出力に出す |
| 7 | `-n` / `--dry-run` を指定 | **1件も削除せず**、1件ごとに `[dry-run] 削除します: <ファイル名>` を出す |
| 8 | 処理の最後 | `対象: <件数>件` を出す。`-n` のときは続けて `ドライランのため、実際には削除していません。` も出す |
| 9 | 対象が0件 | 何も削除せず `対象: 0件` を出し、終了ステータス `0` で終わる |

補足:

- 対象は**指定ディレクトリの直下だけ**です。サブディレクトリの中までは探しません
- `<ファイル名>` は**パスを含めないファイル名だけ**を表示します(`./tmp/a.tmp` ではなく `a.tmp`)
- 拡張子が違うファイル(`-e tmp` のときの `c.txt` など)は、絶対に削除してはいけません
- 正常に処理できた場合の終了ステータスは、削除件数が0件でも `0` です

### 実行例 / 出力フォーマット

`./tmp` に `a.tmp` `b.tmp` `c.txt` の3ファイルがある状態での実行例です。

```text
$ bash work/cleanup_tool.sh -n
[dry-run] 削除します: a.tmp
[dry-run] 削除します: b.tmp
対象: 2件
ドライランのため、実際には削除していません。

$ bash work/cleanup_tool.sh
削除しました: a.tmp
削除しました: b.tmp
対象: 2件

$ bash work/cleanup_tool.sh
対象: 0件

$ bash work/cleanup_tool.sh -d /nosuch
エラー: ディレクトリが見つかりません: /nosuch
```

- 行末に句点(`。`)が付くのは `ドライランのため、実際には削除していません。` の1行だけです
- ラベルと値の区切りは**半角コロン+半角スペース**です(`対象: 2件` / `削除しました: a.tmp`)
- ファイルの表示順は問いません(グロブの展開順で構いません)

<details>
<summary>ヒント1: どんな順番で組み立てるか</summary>

1. 既定値を変数に入れる(`TARGET_DIR="./tmp"` / `EXT="tmp"` / `DRY_RUN="false"`)
2. 長いオプション(`--dry-run` / `--help`)を短いオプションに置き換える
3. `getopts` で `-d` `-e` `-n` `-h` を解析する
4. 対象ディレクトリの存在をチェックする(無ければエラーで終了)
5. `*.<拡張子>` をループで回し、`DRY_RUN` の値で処理を分ける
6. 件数を表示する。ドライランならその旨も表示する

**4を3より先に書いてはいけません。** `-h` はディレクトリが無くても使えるべきなので、存在チェックはオプション解析より後に置きます。

判定の順番を間違えると「`-h` を付けたのにディレクトリが無いと怒られる」という使いにくいツールになります。

</details>

<details>
<summary>ヒント2: 使う文法の具体例</summary>

**ドライランの分岐**

削除する場所が1か所だけになるように書くのがコツです。

```bash
if [[ "$DRY_RUN" == "true" ]]; then
    echo "[dry-run] 削除します: ${filename}"
else
    rm -- "$file"
    echo "削除しました: ${filename}"
fi
```

`rm -- "$file"` の `--` は「これ以降はオプションではなくファイル名」という区切りです。`-foo.tmp` のようにハイフンで始まるファイル名を渡されても、オプションと誤解されなくなります。

**件数の数え方**

```bash
COUNT=0
for file in ...; do
    COUNT=$((COUNT + 1))
done
echo "対象: ${COUNT}件"
```

**ディレクトリの存在チェック**

```bash
if [[ ! -d "$TARGET_DIR" ]]; then
    echo "エラー: ..." >&2
    exit 1
fi
```

`-d` はディレクトリとして存在するかの判定です(ファイルかどうかの `-f` と区別してください)。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

SCRIPT_NAME="$(basename "$0")"
TARGET_DIR="./tmp"
EXT="tmp"
DRY_RUN="false"

usage() {
    echo "使い方: ${SCRIPT_NAME} [-d <ディレクトリ>] [-e <拡張子>] [-n] [-h]"
}

# ここで --dry-run → -n、--help → -h に置き換える

while getopts "d:e:nh" opt; do
    case "$opt" in
        d) TARGET_DIR="$OPTARG" ;;
        # e と n と h をここに書く
        \?) usage >&2; exit 1 ;;
    esac
done
shift $((OPTIND - 1))

# ここでディレクトリの存在チェック

COUNT=0
for file in "${TARGET_DIR%/}"/*."${EXT}"; do
    [[ -f "$file" ]] || continue
    filename="$(basename "$file")"
    COUNT=$((COUNT + 1))
    # ここで DRY_RUN によって処理を分ける
done

echo "対象: ${COUNT}件"
# ここでドライランのときのメッセージ

exit 0
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `-d ./work` を指定しても既定値のまま動く | `getopts "denh"` のように `:` を書き忘れている。値を取るオプションは `d:` `e:` と書く |
| `illegal option -- -` と出て `--dry-run` が使えない | 長いオプションを短いオプションに変換する処理を入れていない。getopts は1文字オプションしか扱えない |
| 対象が0件なのに `対象: 1件` と表示される | グロブがマッチしないとパターン文字列がそのまま入る。ループの先頭に `[[ -f "$file" ]]` による存在チェックを入れる |
| `rm: cannot remove './tmp/*.tmp'` と出る | 同上。存在チェックをしないまま `rm` に渡している |
| `削除しました: ./tmp/a.tmp` とパスまで出る | `basename` を使っていない。`filename="$(basename "$file")"` で名前だけにする |
| `-n` を付けたのにファイルが消えた | 分岐の書き間違い。`if [[ "$DRY_RUN" == "true" ]]` の判定と `rm` の位置を確認する。テスト用のファイルを作り直して再実行する |
| `.txt` まで消えてしまった | ループのパターンが `*` になっている。`*."${EXT}"` と書く |

`./check.sh 05` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。
