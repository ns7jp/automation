## 1. どんな場面で必要になるか

自動化スクリプトは、たいてい**誰も見ていない時間帯**(深夜のcron実行など)に動きます。翌朝「バックアップが取れていない」と言われたとき、手がかりが何も残っていなければ調査のしようがありません。

そこで実務のスクリプトには、必ず「いつ・どのレベルで・何が起きたか」を残すログ処理を入れます。しかも、人が手で実行したときは画面で経過を見たいので、**画面とログファイルの両方に同時に出す**のが定番です。

さらに「INFOが何件、ERRORが何件」という集計を最後に出しておくと、ログ全文を読まなくても成否が一目で分かります。監視システムがログを拾うときの目印にもなります。

この演習では、その共通部品である `log` 関数を自分の手で書きます。案件No.1の `create_users.sh` をはじめ、案件No.1〜No.4のスクリプトはすべて同じ形の `log` 関数を持っています。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| 関数の定義と呼び出し | `名前() { ... }` でまとめた処理を、何度でも呼び出せるようにする仕組み |
| `local` | 関数の中だけで有効な変数。外の同名変数を壊さないための安全装置 |
| `shift` と `"$*"` | 引数を1つずらして、残り全部をひとまとめの文字列として受け取る書き方 |
| `date` の書式 | `date '+%Y-%m-%d %H:%M:%S'` で「2026-09-06 12:34:56」の形にする |
| `tee -a` | 受け取った文字列を、画面とファイルの両方に同時に書き出すコマンド |
| カウンタ変数 | `COUNT=$((COUNT + 1))` で件数を数え、最後に集計を出す |

### 3分でわかる予備知識

**関数と local**

関数(function)とは、いくつかの処理に名前を付けて、何度でも呼び出せるようにしたものです。

```bash
greet() {
    local name="$1"      # local を付けると、この変数は関数の中だけで有効になる
    echo "こんにちは、${name}さん"
}

greet "田中"             # → こんにちは、田中さん
```

`local` を付け忘れると、その変数はスクリプト全体で共有されてしまいます。関数の外に `name` という変数があった場合、それを上書きして壊してしまうため、**関数の中で使う変数には必ず `local` を付ける**と覚えてください。

**shift と "$\*"**

`log "INFO" "対象を3件読み込みました"` のように「1つ目はレベル、2つ目以降はメッセージ本文」という形の関数を作りたいときの定番の書き方です。

```bash
log() {
    local level="$1"     # 1つ目の引数をレベルとして取り出す
    shift                # 引数を1つ左にずらす($2 が $1 になる)
    local message="$*"   # 残りの引数を、空白でつないだ1つの文字列にする
    echo "[${level}] ${message}"
}
```

`"$*"` は「残りの引数全部を空白区切りでつないだ1つの文字列」です。似た書き方に `"$@"` がありますが、こちらは「引数を1つずつ別々のまま」扱います。メッセージ文として1本につなげたい今回は `"$*"` を使います。

**tee -a**

`tee`(ティー)は、水道管のT字管が名前の由来で、流れてきたデータを2方向に分けるコマンドです。

```bash
echo "ログ行" | tee -a ./logs/app.log
```

これで「画面にも表示」しつつ「`./logs/app.log` にも追記」できます。`-a` は append(追記)の意味で、**付け忘れると実行のたびにファイルが上書きされて過去のログが消えます**。

**日時の書式2種類**

```bash
date '+%Y%m%d_%H%M%S'        # → 20260906_123456   ファイル名向け(記号を含めない)
date '+%Y-%m-%d %H:%M:%S'    # → 2026-09-06 12:34:56  ログ行向け(人が読みやすい)
```

ファイル名に `:` や空白を使うと扱いにくくなるため、ファイル名用と表示用で書式を分けるのが慣習です。

**mkdir -p と ${LOG_DIR%/}**

```bash
mkdir -p ./logs/2026/09     # -p を付けると、途中のディレクトリもまとめて作る
                            # 既にある場合もエラーにならない
```

`${LOG_DIR%/}` は「変数の末尾にスラッシュがあれば取り除く」というパラメータ展開です。`-l /var/log/` のように末尾に `/` を付けて指定されても、パスが `/var/log//with_log_...` と二重にならないようにするための小技です。

## 3. 課題

`work/with_log.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | オプションなしで実行 | ログ出力先を `./logs` として処理を行う |
| 2 | `-l <ディレクトリ>` を指定 | ログ出力先をそのディレクトリに変える |
| 3 | ログ出力先が存在しない | `mkdir -p` で作る。`a/b/c` のような多段のパスも作れること |
| 4 | ログ出力先を作れない | 標準エラー出力に `エラー: ログディレクトリを作成できません: <パス>` を出し、終了ステータス `1` |
| 5 | 未定義のオプション(例: `-z`) | 使い方を**標準エラー出力**に表示し、終了ステータス `1` |
| 6 | 処理が正常に進んだ | 本体処理の5行とサマリ1行を、**画面とログファイルの両方**に出す |
| 7 | ERROR を1件以上記録した | 終了ステータス `1` で終わる(今回のスクリプトは必ずERRORが1件出るので `1` になる) |

### ログファイル名

```text
<ログ出力ディレクトリ>/with_log_<YYYYMMDD>_<HHMMSS>.log
```

例: `./logs/with_log_20260906_123456.log`

### ログ1行の書式

```text
[YYYY-MM-DD HH:MM:SS] [レベル] メッセージ
```

- 日時は角括弧 `[ ]` で囲む。区切りは半角スペース1個
- レベルも角括弧 `[ ]` で囲む。使うレベルは `INFO` / `WARN` / `ERROR` の3種類(すべて半角大文字)
- レベルの後ろは半角スペース1個を空けてメッセージ本文

### 本体処理として記録する内容(この5行だけ。順番も守ること)

| レベル | メッセージ |
|---|---|
| INFO | `===== 処理を開始します =====` |
| INFO | `対象を3件読み込みました` |
| WARN | `1件は対象外のためスキップしました` |
| ERROR | `1件の処理に失敗しました` |
| INFO | `===== 処理を終了します =====` |

### サマリ行

本体処理の5行を数えた結果を、最後に `INFO` レベルで1行だけ出します。

```text
INFO: 3件 / WARN: 1件 / ERROR: 1件
```

- 件数は**本体処理で記録した5行ぶん**です。サマリ行そのものは数に入れません
- 上の5行を仕様どおりに記録すれば、件数は必ず `INFO: 3件 / WARN: 1件 / ERROR: 1件` になります
- ログを増やしたり減らしたりすると件数が合わなくなるので、5行から増減させないでください

### 実行例 / 出力フォーマット

```text
$ bash work/with_log.sh
[2026-09-06 12:34:56] [INFO] ===== 処理を開始します =====
[2026-09-06 12:34:56] [INFO] 対象を3件読み込みました
[2026-09-06 12:34:56] [WARN] 1件は対象外のためスキップしました
[2026-09-06 12:34:56] [ERROR] 1件の処理に失敗しました

[2026-09-06 12:34:56] [INFO] INFO: 3件 / WARN: 1件 / ERROR: 1件
$ echo $?

$ cat logs/with_log_20260906_123456.log
[2026-09-06 12:34:56] [INFO] ===== 処理を開始します =====
[2026-09-06 12:34:56] [INFO] 対象を3件読み込みました

```

画面に出た内容とログファイルの内容が**同じ**であることがポイントです。

## 5. ヒント

自力で20分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: どんな順番で組み立てるか</summary>

処理の順番を間違えると動きません。次の順で組み立ててください。

1. 既定値(`LOG_DIR="./logs"`)とカウンタ変数(`INFO_COUNT=0` など)を用意する
2. `getopts` で `-l` を受け取り、指定があれば `LOG_DIR` を上書きする
3. `mkdir -p "$LOG_DIR"` でディレクトリを作る(失敗したら終了)
4. ログファイルのパス `LOG_FILE` を組み立てる
5. `log` 関数を定義する
6. 本体処理の5行を `log` で記録する
7. サマリを `log` で記録する
8. `ERROR_COUNT` を見て `exit 1` か `exit 0` を返す

**3と4を5より後に書いてはいけません。** `log` 関数が使う `LOG_FILE` は、関数を呼び出す時点で値が入っている必要があります(関数を「定義する」順番は自由ですが、「呼び出す」時点では準備が終わっている必要がある、と考えてください)。

</details>

<details>
<summary>ヒント2: 使う文法の具体例</summary>

**オプションの受け取り**

```bash
while getopts "l:" opt; do
    case "$opt" in
        l)  LOG_DIR="$OPTARG" ;;   # : を付けたオプションの値は $OPTARG に入る
        \?) usage >&2; exit 1 ;;   # 未定義のオプションが来たとき
    esac
done
```

**ディレクトリ作成の失敗判定**

```bash
if ! mkdir -p "$LOG_DIR"; then
    echo "エラー: ..." >&2
    exit 1
fi
```

`if ! コマンド; then` は「そのコマンドが失敗したら」という意味です。

**件数の数え方**

```bash
case "$level" in
    INFO)  INFO_COUNT=$((INFO_COUNT + 1)) ;;
    WARN)  WARN_COUNT=$((WARN_COUNT + 1)) ;;
    ERROR) ERROR_COUNT=$((ERROR_COUNT + 1)) ;;
esac
```

`$(( ))` は算術式(計算)の書き方です。この `case` を `log` 関数の中に置けば、ログを出すたびに自動で数えられます。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

SCRIPT_NAME="$(basename "$0")"
LOG_DIR="./logs"
TIMESTAMP="$(date '+%Y%m%d_%H%M%S')"

INFO_COUNT=0
WARN_COUNT=0
ERROR_COUNT=0

usage() {
    echo "使い方: ${SCRIPT_NAME} [-l <ログ出力ディレクトリ>]"
}

# ここで getopts による -l の解析

# ここで mkdir -p と失敗時のエラー処理

LOG_FILE="${LOG_DIR%/}/with_log_${TIMESTAMP}.log"

log() {
    local level="$1"
    shift
    local message="$*"
    local now
    now="$(date '+%Y-%m-%d %H:%M:%S')"

    # ここでレベルごとの件数を数える

    echo "[${now}] [${level}] ${message}" | tee -a "$LOG_FILE"
}

log "INFO" "===== 処理を開始します ====="
# ここに残り4行

log "INFO" "INFO: ${INFO_COUNT}件 / WARN: ${WARN_COUNT}件 / ERROR: ${ERROR_COUNT}件"

# ここで ERROR_COUNT を見て終了ステータスを決める
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `tee: ./logs/with_log_.log: No such file or directory` | `mkdir -p` より先に `log` を呼んでいる、または `TIMESTAMP` が空。処理の順番を見直す |
| ログファイルが毎回上書きされて1行しか残らない | `tee` に `-a` を付け忘れている。`tee -a "$LOG_FILE"` と書く |
| `with_log_.log` のようにファイル名の日時が空になる | `date` の書式にシングルクォートを付け忘れている。`date '+%Y%m%d_%H%M%S'` と書く |
| サマリが `INFO: 0件 / WARN: 0件 / ERROR: 0件` になる | カウンタを増やす処理を書いていない、または `log` を呼ぶ前に集計している |
| サマリが `INFO: 4件` になる | 仕様に無いログ行を追加している。本体処理は5行だけにする |
| 画面には出るがログファイルが空 | `echo ... > "$LOG_FILE"` のようにリダイレクトだけしている。`tee -a` につないで出力する |
| `line 20: LOG_FILE: unbound variable` | `set -u` の状態で、値を入れる前に `LOG_FILE` を使っている |

`./check.sh 04` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。

1. `-v`(verbose)オプションを追加し、指定が無いときは `INFO` を画面に出さず、ログファイルにだけ残す(`tee` の代わりに `>> "$LOG_FILE"` と使い分ける)
2. `ERROR` レベルのときだけ、メッセージを標準エラー出力にも出す(`>&2`)
3. 30日より古いログファイルを起動時に削除する(`find "$LOG_DIR" -name '*.log' -mtime +30 -delete`)。実行前に `-delete` を外して対象を確認する習慣も一緒に身につける
