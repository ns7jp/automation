## 1. どんな場面で必要になるか

ex07 から ex09 で作ってきたスクリプトは、**誰かが実行しなければ1回も動きません**。バックアップは毎日、ログ監視は5分おき、世代削除は月に1度。この「決まった時刻に自動で動かす」役目を担うのが **cron (クロン)** です。Linuxサーバーなら標準で入っている常駐プログラムで、登録された表を1分ごとに見て、時刻が合致した行のコマンドを実行します。

運用の現場では、サーバーを引き継ぐときにまず `crontab -l` を叩いて「このサーバーは何を、いつ動かしているのか」を確認します。逆に言うと、あなたが書いた cron の定義は**あとから他人が読むドキュメント**でもあります。読めない cron 定義は「怖くて消せない謎のジョブ」になり、何年も放置されます。

この演習では、案件No.2の `crontab.example` と同じ形式で、4つのジョブを持つ cron 定義ファイルを書きます。シェルスクリプトではなく設定ファイルを書く演習なので、`bash -n` による構文チェックはありません。そのぶん、書式を1文字ずつ正確に書くことが求められます。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| 5つの時刻フィールド | 左から 分 / 時 / 日 / 月 / 曜日。順番を間違えると別の時刻になる |
| `*` と範囲と間隔 | `*` は毎回、`9-18` は範囲、`*/5` は間隔 |
| 絶対パスで書く理由 | cron の `PATH` は最小限。`./backup.sh` では見つからない |
| 出力のリダイレクト | `>>` で追記、`> /dev/null` で捨てる、`2>&1` でエラーもまとめる |
| `MAILTO` | ジョブが出力を出したときのメール送信先 |
| `crontab` コマンド | `-l` で確認、`-e` で編集。`/etc/cron.d` との違い |

### 3分でわかる予備知識

**cron の1行はこう読む**

```text
分 時 日 月 曜日 実行するコマンド

30  2  *  *  *   /opt/scripts/backup.sh
│   │  │  │  └── 曜日 (0-7、0と7はどちらも日曜)
│   │  │  └───── 月   (1-12)
│   │  └──────── 日   (1-31)
│   └─────────── 時   (0-23)
└─────────────── 分   (0-59)
```

上の例は「毎日 2時30分」です。**分が先、時が後**である点に注意してください。`2 30 * * *` と書くと「毎日 30時2分」になり、時が範囲外なのでエラーになります。

| 書き方 | 意味 | 例 |
|---|---|---|
| `*` | その項目を絞り込まない (毎回) | `* * * * *` → 毎分 |
| `5` | ちょうどその値のとき | `5 * * * *` → 毎時5分 |
| `9-18` | 範囲 | `0 9-18 * * *` → 9時から18時の毎時0分 (10回) |
| `*/5` | その間隔ごと | `*/5 * * * *` → 0,5,10,...,55分 (毎時12回) |
| `1,15` | 列挙 | `0 0 1,15 * *` → 毎月1日と15日の0時 |
| `1-5` (曜日) | 月曜から金曜 | 曜日は 0=日 1=月 2=火 3=水 4=木 5=金 6=土 |

**出力のリダイレクト**

cron は、ジョブが何か出力すると、その内容を実行ユーザー宛にメールで送ろうとします。メールサーバーが無いと送信エラーがたまり続けるだけなので、実務では**必ず出力先を指定します**。

```bash
>> /var/log/backup.log 2>&1     # 標準出力も標準エラー出力もログに追記する
>  /dev/null 2>&1               # 両方とも捨てる
```

`2>&1` は「標準エラー出力 (2番) を標準出力 (1番) と同じ行き先に送る」という意味です。**必ず `>>` や `>` より後ろに書きます**。先に書くと、その時点の行き先 (画面) にコピーされてしまい、エラーだけログに残りません。

**なぜ絶対パスで書くのか**

cron から実行されるコマンドの `PATH` は、ログイン時のシェルとは別物で、`/usr/bin:/bin` 程度しかありません。カレントディレクトリも `/` やユーザーのホームになります。

```text
* * * * * ./backup.sh          # 動かない。どこの ./ なのか cron は知らない
* * * * * backup.sh            # 動かない。PATH に無い
* * * * * /opt/scripts/backup.sh   # これなら確実に動く
```

「手で実行すると動くのに cron だと動かない」の原因は、9割がこのパスの問題です。

**`crontab` コマンド**

```bash
crontab -l              # 今の登録内容を表示する
crontab -e              # エディタで編集する (保存時に書式チェックが入る)
crontab backup_cron.txt # ファイルの内容で丸ごと登録する (今回の形式)
```

ユーザーごとの `crontab` に対して、システム全体用の `/etc/cron.d/` に置くファイルもあります。こちらは**実行ユーザーの列が増える**点が違います (`30 2 * * * root /opt/scripts/backup.sh`)。今回はユーザーの `crontab` 形式なので、ユーザー名の列は書きません。

## 3. 課題

`work/backup_cron.txt` を編集し、次の4つのジョブと `MAILTO` を書いてください。ファイルは `crontab backup_cron.txt` でそのまま登録できる形式にします。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 実行結果メールの宛先 | `MAILTO="admin@example.com"` を行の先頭から書く |
| 2 | 毎日 深夜2時30分 | `/opt/scripts/backup.sh` を実行し、出力を `>> /var/log/backup.log 2>&1` で追記する |
| 3 | 月曜から金曜の 9時から18時までの毎時0分 | `/opt/scripts/health_check.sh` を実行し、出力を `>> /var/log/health_check.log 2>&1` で追記する |
| 4 | 5分ごと | `/opt/scripts/log_watch.sh` を実行し、出力を `> /dev/null 2>&1` で捨てる |
| 5 | 毎月1日の 3時0分 | `/opt/scripts/rotate_backups.sh -d /backup -g 7` を実行し、出力を `>> /var/log/rotate.log 2>&1` で追記する |
| 6 | 実行行の直前 | `#` で始まる日本語の説明コメント行を書く (ファイル全体で4行以上) |
| 7 | 実行行の数 | `MAILTO` を除いて、ちょうど4行にする |
| 8 | 雛形の `TODO` 行 | すべて消す |
| 9 | ファイルの最後 | 改行で終わらせる |

- コマンドは**すべて絶対パス**で書きます
- 各フィールドの区切りは**半角スペース**です (何個でもかまいませんが、1個が読みやすい)
- リダイレクトは**コマンドと引数の後ろ**に書きます

### 出力フォーマット

完成したファイルは、次のような形になります (`<...>` の部分をあなたが書きます)。

```text
MAILTO="admin@example.com"

# 毎日 深夜2時30分 にバックアップを取得する
30 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1

# <説明コメント>
<0 9-18 * * 1-5 から始まる行>

# <説明コメント>
<*/5 * * * * から始まる行>

# <説明コメント>
<0 3 1 * * から始まる行>
```

1行目のジョブ (ジョブ1) は、そのまま書き写して正解になる例として載せています。残り3行を自分で組み立ててください。

## 5. ヒント

自力で15分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: 日本語から5フィールドへの翻訳のしかた</summary>

日本語の条件を、左から順に埋めていきます。指定が無い項目は `*` です。

| 日本語 | 分 | 時 | 日 | 月 | 曜日 |
|---|---|---|---|---|---|
| 毎日 深夜2時30分 | `30` | `2` | `*` | `*` | `*` |
| 月〜金の9時から18時までの毎時0分 | `0` | ? | `*` | `*` | ? |
| 5分ごと | ? | `*` | `*` | `*` | `*` |
| 毎月1日の3時0分 | `0` | `3` | ? | `*` | `*` |

「毎時0分」は「分が0のとき」なので分フィールドが `0` です。「5分ごと」は分フィールドに間隔を書きます。「毎月1日」は日フィールドを `1` にします。**曜日を `*` 以外にすると、日の指定と併用したときの挙動が変わる**ので、日を指定するときは曜日を `*` のままにしてください。

</details>

<details>
<summary>ヒント2: リダイレクトの書き方</summary>

コマンドと引数を書き終えた**後ろ**に付けます。

```text
30 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
                                  └─ ここから後ろがリダイレクト
```

| やりたいこと | 書き方 |
|---|---|
| ログに追記する (前回の内容を残す) | `>> /var/log/xxx.log 2>&1` |
| ログを毎回上書きする | `> /var/log/xxx.log 2>&1` |
| 出力を捨てる | `> /dev/null 2>&1` |

オプション付きのコマンドでも同じです。オプションはコマンドのすぐ後ろ、リダイレクトは最後です。

```text
0 3 1 * * /opt/scripts/rotate_backups.sh -d /backup -g 7 >> /var/log/rotate.log 2>&1
```

</details>

<details>
<summary>ヒント3: ファイル全体の骨組み</summary>

```text
MAILTO="admin@example.com"

# 毎日 深夜2時30分 にバックアップを取得し、結果をログへ追記する
30 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1

# 平日の9時から18時まで、毎時0分に死活監視を実行する
0 9-18 * * ? /opt/scripts/health_check.sh >> ? 2>&1

# 5分ごとにログ監視を実行する。出力は捨てる
? * * * * /opt/scripts/log_watch.sh > ? 2>&1

# 毎月1日の3時に、古いバックアップを7世代残して削除する
0 3 ? * * /opt/scripts/rotate_backups.sh -d /backup -g 7 >> ? 2>&1
```

`?` の部分を埋めれば完成です。コメントの文面は、この例のとおりでなくてもかまいません。「いつ・何を・なぜ」が伝わる日本語であれば自由です。

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 5分ごとのつもりが1時間に1回しか動かない | `*/5` と書くべきところを `5` と書いている。`5` は「毎時5分に1回」の意味 |
| `crontab -e` で保存すると `errors in crontab file, can't install` と出る | フィールドの数が5個になっていない、または時刻の値が範囲外 (時に `24` など)。行を数えて確認する |
| 日曜だけ動かない / 日曜に2回動く | 曜日は `0` と `7` がどちらも日曜。`1-7` と書くと日曜が抜け、月曜から日曜のつもりでも土曜までになる。月曜から金曜は `1-5` |
| `date +\%Y` を書いたら動かない | cron では `%` が改行の意味になる。コマンド中の `%` は `\%` とエスケープする。スクリプト側に閉じ込めてしまうのが確実 |
| 手で実行すると動くのに cron だと動かない | 相対パス (`./backup.sh`) で書いている、または `PATH` に依存している。すべて絶対パスで書く |
| 最終行のジョブだけ実行されない | ファイルの最後が改行で終わっていない。エディタで最終行の末尾に改行を入れる |

`./check.sh 10` が失敗したときは、**「期待」に表示される正規表現**を読んでください。`\*` は「文字としての `*`」、`+` は「直前の文字が1個以上」という意味で、期待している並びがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。

1. `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` と `SHELL=/bin/bash` を先頭に書き足し、cron の実行環境を明示する
2. 同じ内容を `/etc/cron.d/backup-automation` 形式 (実行ユーザーの列がある形式) で書き直し、2つの形式の違いを説明できるようにする
3. `flock -n /var/run/backup.lock` を使って、前回の実行が終わっていないときに二重起動しないようにする
