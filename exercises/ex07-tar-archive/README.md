## 1. どんな場面で必要になるか

「Webサーバーのコンテンツを毎晩バックアップしておいてください」は、運用の現場でいちばん最初に任される仕事のひとつです。手作業で `tar` を叩くこともできますが、毎晩3時に人間が起きているわけにはいきません。そこで、**引数を渡せば同じ手順で必ず同じ形のアーカイブを作るスクリプト**を先に用意します。

このとき地味に効いてくるのが「アーカイブの中身の作り方」です。復元するときに `/home/ubuntu/work/var/www/html/...` のような絶対パスが展開されてしまい、本番のファイルを上書きしてしまう事故は実際に起きます。また、サイズの大半を占めるアクセスログまで毎晩固めてしまうと、保存先の容量があっという間に足りなくなります。

この演習では、案件No.2の `backup.sh` が最初にやっている「対象を tar.gz に固めて保存先に置く」部分だけを取り出して自分の手で書きます。世代管理(古いバックアップの削除)は次の [ex08](../ex08-rotate-generations/README.md) で扱います。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| `tar -czf` | 複数のファイルを1つに束ね(c)、gzipで圧縮し(z)、指定した名前で保存する(f) |
| `-C <ディレクトリ>` | 「そのディレクトリに移動してから固める」オプション。絶対パスの混入を防ぐ |
| `--exclude=<パターン>` | アーカイブに入れたくないファイルを除外する |
| 日付入りのファイル名 | `date` の出力を名前に埋め込み、いつのバックアップか一目で分かるようにする |
| `du -h` | ファイルやディレクトリのサイズを人間が読みやすい単位で表示する |
| コマンドの成否判定 | `if tar ...; then` のように、コマンドの終了ステータスで分岐する |

### 3分でわかる予備知識

**tar とは**

`tar` は「複数のファイルとディレクトリを、階層構造を保ったまま1個のファイルにまとめる」コマンドです。まとめただけのファイルは `.tar`、さらに gzip で圧縮すると `.tar.gz` になります。

```bash
tar -czf backup.tar.gz data      # data ディレクトリを backup.tar.gz に固める
tar -tzf backup.tar.gz           # 中身の一覧を表示する(展開はしない)
tar -xzf backup.tar.gz           # 展開する
```

オプションの意味は次のとおりです。覚え方は「**c** reate / g **z** ip / **f** ile」です。

| 文字 | 意味 |
|---|---|
| `c` | create。新しいアーカイブを作る |
| `t` | list。中身の一覧を表示する |
| `x` | extract。展開する |
| `z` | gzip で圧縮/展開する |
| `f` | 直後にアーカイブのファイル名を指定する |

**作ったら必ず `tar -tzf` で中身を確認する**のが実務の習慣です。バックアップは「作れたこと」ではなく「戻せること」が価値なので、中身を見ないまま安心してはいけません。

**なぜ `-C` を使うのか**

`-C <ディレクトリ>` は「そのディレクトリに移動してから、続く名前を固める」という意味です。

```bash
# 悪い例: アーカイブの中に var/www/html/... という長いパスが入る
tar -czf backup.tar.gz /var/www/html

# 良い例: アーカイブの中は html/... だけになる
tar -czf backup.tar.gz -C /var/www html
```

`tar` は絶対パスを渡すと先頭の `/` を取り除いて `var/www/html/index.html` のように保存します。これを別のサーバーの `/tmp` などで展開すると `/tmp/var/www/html/...` という意図しない場所にファイルが散らばります。`-C` で**親ディレクトリを基準にする**と、アーカイブの中身が `html/index.html` のように短くなり、どこで展開しても扱いやすくなります。

「対象ディレクトリの親」と「対象ディレクトリの名前」は、次の2つのコマンドで取り出せます。

```bash
dirname  /var/www/html    # → /var/www   (最後の要素を取り除いたパス)
basename /var/www/html    # → html       (最後の要素だけ)
```

**除外の指定**

```bash
tar -czf backup.tar.gz --exclude='*.log' -C /var/www html
```

`--exclude` のパターンはシングルクォートで囲みます。囲まないと、`*.log` を**シェルが先に**カレントディレクトリのファイル名に展開してしまい、意図した除外になりません。

**コマンドの成否で分岐する**

```bash
if tar -czf backup.tar.gz data; then
    echo "成功した"
else
    echo "失敗した" >&2
fi
```

`if` は「コマンドの終了ステータスが0かどうか」で分岐します。バックアップは失敗しても画面を見ている人がいないことが多いので、**失敗を必ず終了ステータス1として呼び出し側に伝える**ことが重要です。

**サイズの表示**

```bash
du -h backup.tar.gz          # → 4.0K   backup.tar.gz
du -h backup.tar.gz | cut -f1   # → 4.0K  (サイズだけ取り出す)
```

`du` の出力は「サイズ<タブ>パス」という形式なので、`cut -f1` で1列目だけを取り出します。

## 3. 課題

`work/make_archive.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 引数を2つ(対象ディレクトリ・保存先ディレクトリ)付けて実行 | アーカイブを作成し、完了メッセージを標準出力に表示して終了ステータス `0` |
| 2 | 引数がちょうど2個でない(0個・1個・3個以上) | 使い方を**標準エラー出力**に表示し、終了ステータス `1` |
| 3 | 対象ディレクトリが存在しない | `エラー: 対象ディレクトリが見つかりません: <パス>` を**標準エラー出力**に表示し、終了ステータス `1` |
| 4 | 保存先ディレクトリが存在しない | `mkdir -p` で作成してから処理を続ける(エラーにしない) |
| 5 | アーカイブのファイル名 | `backup_<YYYYMMDD>_<HHMMSS>.tar.gz` |
| 6 | アーカイブの中身 | 対象ディレクトリ名から始まる相対パスにする。`*.log` は除外する |
| 7 | `tar` が成功したとき | `バックアップ完了: <保存先のパス> (サイズ: <du -h の結果>)` を標準出力に表示し、終了ステータス `0` |
| 8 | `tar` が失敗したとき | `エラー: バックアップに失敗しました` を**標準エラー出力**に表示し、終了ステータス `1` |

### 実行例

```text
$ bash make_archive.sh data backup
バックアップ完了: backup/backup_20260906_031500.tar.gz (サイズ: 4.0K)

$ tar -tzf backup/backup_20260906_031500.tar.gz
data/
data/index.html
data/style.css
data/sub/
data/sub/note.txt
```

- `a.log` はアーカイブの一覧に**出てきません**(仕様6の除外)
- アーカイブ内のパスは `data/` から始まります。対象を `/tmp/xxx/data` のように絶対パスで指定した場合も同じです

### 出力フォーマット

完了メッセージの書式は次のとおりです。**半角スペース・半角括弧・コロンの位置まで**合わせてください。

```text
バックアップ完了: backup/backup_20260906_031500.tar.gz (サイズ: 4.0K)
```

- `バックアップ完了: ` の後ろは**保存したアーカイブのパス**(保存先ディレクトリ + ファイル名)
- 続けて**半角スペース1つ**、`(サイズ: ` 、`du -h` の結果、`)`

エラーメッセージの書式は次のとおりです。

```text
エラー: 対象ディレクトリが見つかりません: nosuchdir
エラー: バックアップに失敗しました
```

使い方メッセージには「使い方」という単語を必ず含めてください。例:

```text
使い方: make_archive.sh <バックアップ対象ディレクトリ> <保存先ディレクトリ>
```

<details>
<summary>ヒント1: どういう順番で処理を組み立てるか</summary>

バックアップスクリプトは「危ないことをする前に、前提を全部確認する」順番で書きます。

1. 引数の個数を確認する(足りなければ使い方を出して終了)
2. 対象ディレクトリが本当に存在するか確認する
3. 保存先ディレクトリを用意する(無ければ作る)
4. 日時からアーカイブ名を組み立てる
5. `tar` を実行する
6. 成功したか失敗したかで、出すメッセージと終了ステータスを変える

3番目までは ex01・ex02 でやったことの組み合わせです。新しいのは4〜6だけだと考えると気が楽になります。

<details>
<summary>ヒント2: 使う文法とコマンドの具体例</summary>

**日時からファイル名を作る**

```bash
TIMESTAMP="$(date '+%Y%m%d_%H%M%S')"   # → 20260906_031500
ARCHIVE_NAME="backup_${TIMESTAMP}.tar.gz"
```

`${TIMESTAMP}` のように波括弧で囲むのは、`$TIMESTAMP.tar.gz` と書いたときに変数名がどこまでか分かりにくくなるのを防ぐためです。

**保存先ディレクトリを用意する**

```bash
mkdir -p "$DEST_DIR"    # -p : 親ごと作る。既に存在してもエラーにしない
```

**パスを組み立てる**

```bash
ARCHIVE_PATH="${DEST_DIR%/}/${ARCHIVE_NAME}"
```

`${DEST_DIR%/}` は「末尾がスラッシュならそれを取り除く」という書き方です。`backup/` と指定されても `backup//backup_...tar.gz` にならずに済みます。

**tar の実行と成否の判定**

```bash
if tar -czf "$ARCHIVE_PATH" --exclude='*.log' -C "$SRC_PARENT" "$SRC_BASE"; then
    # 成功したときの処理
else
    # 失敗したときの処理
fi
```

`SRC_PARENT` と `SRC_BASE` は `dirname` と `basename` で作ります。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

usage() {
    echo "使い方: $(basename "$0") <バックアップ対象ディレクトリ> <保存先ディレクトリ>"
}

if [[ "$#" -ne 2 ]]; then
    usage >&2
    exit 1
fi

SRC_DIR="$1"
DEST_DIR="$2"

if [[ ! -d "$SRC_DIR" ]]; then
    echo "エラー: 対象ディレクトリが見つかりません: ${SRC_DIR}" >&2
    exit 1
fi

mkdir -p "$DEST_DIR"

ARCHIVE_PATH="..."          # backup_<日時>.tar.gz を組み立てる
SRC_PARENT="$(dirname "$SRC_DIR")"
SRC_BASE="$(basename "$SRC_DIR")"

if tar ... ; then
    ARCHIVE_SIZE="$(du -h "$ARCHIVE_PATH" | cut -f1)"
    echo "バックアップ完了: ..."
    exit 0
else
    echo "エラー: バックアップに失敗しました" >&2
    exit 1
fi
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `tar: Removing leading '/' from member names` と出る | 対象を絶対パスのまま `tar` に渡している。`-C "$(dirname ...)"` と `"$(basename ...)"` の組み合わせに直す |
| `.log` が除外されない | `--exclude=*.log` をクォートしていない。シェルが先に展開してしまうので `--exclude='*.log'` と書く |
| `tar (child): backup/backup_....tar.gz: Cannot open: No such file or directory` | 保存先ディレクトリを作る前に `tar` を実行している。`mkdir -p "$DEST_DIR"` を先に書く |
| ファイル名が `backup_.tar.gz` になる | `date` のフォーマットを取り込めていない。`$(date '+%Y%m%d_%H%M%S')` のようにコマンド置換で囲む |
| サイズの表示が `4.0K   backup/....tar.gz` になる | `du -h` の出力はサイズとパスのタブ区切り。`cut -f1` でサイズだけ取り出す |
| `tar` が失敗しても終了ステータスが0 | `tar` の結果を見ていない。`if tar ...; then ... else ... fi` で分岐する |

`./check.sh 07` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。

1. `-h` / `--help` を受け付けて、使い方を標準出力に表示して終了ステータス `0` で終わるようにする
2. 作成後に `tar -tzf` を実行し、アーカイブが壊れていないかを自己検証してから完了メッセージを出す
3. 除外パターンを第3引数または `--exclude` オプションで指定できるようにし、既定値は `*.log` のままにする
