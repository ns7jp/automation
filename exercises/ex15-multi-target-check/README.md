## 1. どんな場面で必要になるか

サーバーが1台だけなら、朝いちばんにブラウザで開いて「見えているから大丈夫」で済みます。ところが事業が伸びてWebサーバー2台・DBサーバー1台・APIサーバー1台と増えると、毎朝の目視確認は5分では終わらず、担当者が休んだ日には誰も見ていない状態になります。

実務でまず作るのは「監視対象の一覧を書いたファイルを読んで、上から順に生きているか確かめ、結果を1画面にまとめて出す」小さなスクリプトです。ここで重要なのは、**監視対象をスクリプトの中に直接書かない**ことです。サーバーが増減するたびにスクリプト本体を書き換えていると、運用担当者がロジックを壊してしまいます。対象は別ファイル(定義ファイル)に切り出し、スクリプトはそれを読むだけにします。

この演習では、案件No.4 `health_check.sh` の中核である「定義ファイルを1行ずつ読み、種別に応じて ping か HTTP でチェックし、最後に集計する」部分を自分の手で書きます。案件本体では `targets.conf` がその定義ファイルにあたります。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| `while IFS=',' read` | カンマ区切りのファイルを1行ずつ、列に分けて読み込む定番の書き方 |
| コメント行・空行の読み飛ばし | 設定ファイルには人間向けの注釈が入る。`#` と空行は必ず無視する |
| `case` による分岐 | 「種別が ping なら / http なら / それ以外なら」を読みやすく書く |
| `ping` の終了ステータス | 応答があれば0、無ければ0以外。画面の文字ではなく数字で判定する |
| `curl -o /dev/null -w '%{http_code}'` | 本文は捨てて、HTTPステータスコードだけを取り出す書き方 |
| 集計と終了ステータス | 異常が1件でもあれば `exit 1`。cronや上位の仕組みに成否を伝える |

### 3分でわかる予備知識

**カンマ区切りのファイルを1行ずつ読む**

```bash
while IFS=',' read -r name type dest; do
    echo "名前=${name} 種別=${type} 宛先=${dest}"
done < "targets.conf"
```

- `IFS=','` は「区切り文字はカンマ」という指定です。IFS は Internal Field Separator (内部フィールド区切り文字) の略で、シェルが文字列を列に分けるときの目印です。
- `read -r name type dest` は、1行を3つの変数に分けて入れます。`-r` はバックスラッシュを特別扱いしないためのオプションで、付けるのが定番です。
- `done < "ファイル"` で、ループ全体の入力をファイルにつなぎます。

**コメント行と空行を読み飛ばす**

```bash
# $name が空(空行)、または # で始まる(コメント行)なら次の行へ
[[ -z "$name" || "$name" == \#* ]] && continue
```

`continue` は「このループの残りをやめて次の1周に進む」命令です。`\#*` の `\` は `#` をコメント開始と誤解させないためのエスケープ (打ち消し記号) です。

**ping で生きているか調べる**

```bash
if ping -c 1 -W 2 "web01" > /dev/null 2>&1; then
    echo "応答あり"
else
    echo "応答なし"
fi
```

- `-c 1` は送るパケットの回数、`-W 2` は応答を待つ秒数です。
- `> /dev/null 2>&1` は「画面に出す文字はすべて捨てる」という意味です。ここで使いたいのは**表示内容ではなく終了ステータス**だけだからです。

**curl でHTTPステータスコードだけを取り出す**

```bash
code="$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 "http://web01/")"
echo "$code"   # → 200
```

- `-s` は進捗表示を出さない (silent)、`-o /dev/null` は本文を捨てる、`-w '%{http_code}'` は「ステータスコードだけを出力する」という指定です。
- `--max-time 5` は最大5秒で諦めるという保険です。
- 接続そのものに失敗した場合、`%{http_code}` は `000` になります。「つながらなかった」も異常として扱えるので、そのまま判定に使えます。

**HTTPステータスコードの分類**

| 範囲 | 意味 | 監視での扱い |
|---|---|---|
| 200〜299 | 成功 | 正常 |
| 300〜399 | リダイレクト | この演習では異常として扱う |
| 400〜499 | クライアント側の誤り (404 など) | 異常 |
| 500〜599 | サーバー側の障害 (500 など) | 異常 |
| 000 | 接続できなかった | 異常 |

「200番台かどうか」は正規表現で素直に書けます。

```bash
if [[ "$code" =~ ^2[0-9][0-9]$ ]]; then
    echo "正常"
fi
```

**オプションの解析 (getopts)**

```bash
while getopts ":t:h" opt; do
    case "$opt" in
        t) targets_file="$OPTARG" ;;   # -t の後ろの値が $OPTARG に入る
        h) usage; exit 0 ;;
        *) usage >&2; exit 1 ;;
    esac
done
```

`":t:h"` の読み方は、先頭の `:` が「未知のオプションを自分で処理する」、`t:` が「-t は値を取る」、`h` が「-h は値を取らない」です。

## 3. 課題

`work/health_check.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 定義ファイルの書式

1行に1台、カンマ区切りで3列です。

```text
<表示名>,<種別>,<宛先>
```

- `<表示名>`: 画面に出す名前 (例: `web01`)
- `<種別>`: `ping` または `http`
- `<宛先>`: 種別が `ping` ならホスト名、`http` ならURL

例:

```text
# 監視対象の一覧 (この行はコメントなので読み飛ばされる)
web01,ping,web01

web02,http,http://web02/
```

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | `-h` を指定 | 使い方を**標準出力**に表示し、終了ステータス `0` で終わる |
| 2 | `-t` を指定しない | `使い方` を含むエラーを**標準エラー出力**に表示し、終了ステータス `1` で終わる |
| 3 | `-t` に存在しないファイルを指定 | `見つかりません` を含むエラーを**標準エラー出力**に表示し、終了ステータス `1` で終わる |
| 4 | 行が空行、または `#` で始まる | その行は読み飛ばす (何も表示しない) |
| 5 | 種別が `ping` で応答あり | `[OK] <表示名> (ping)` を表示する |
| 6 | 種別が `ping` で応答なし | `[NG] <表示名> (ping: 応答なし)` を表示する |
| 7 | 種別が `http` で200番台 | `[OK] <表示名> (http: <コード>)` を表示する |
| 8 | 種別が `http` で200番台以外 (`000` を含む) | `[NG] <表示名> (http: <コード>)` を表示する |
| 9 | 種別が `ping` / `http` のどちらでもない | `[SKIP] <表示名> 種別が不正です: <種別>` を表示して次の行へ進む |
| 10 | すべての行を処理し終えたあと | `正常: <件数>件 / 異常: <件数>件` を表示する |
| 11 | 異常が1件以上 | 終了ステータス `1` で終わる |
| 12 | 異常が0件 | 終了ステータス `0` で終わる |

補足:

- `[SKIP]` になった行は、正常にも異常にも数えません。したがって `[SKIP]` だけがあって `[NG]` が0件なら、終了ステータスは `0` です。
- ping は `ping -c 1 -W 2 <宛先>` を実行し、**終了ステータス**で成否を判定します。
- http は `curl -s -o /dev/null -w '%{http_code}' --max-time 5 <宛先>` で取得した**HTTPステータスコード**で判定します。

### 実行例 / 出力フォーマット

定義ファイル `targets.conf` が次の内容だとします。

```text
# 本番Webサーバー
web01,ping,web01

web02,http,http://web02/
web03,ping,web03
web04,http,http://web04/
web05,pong,web05
```

`web03` が停止中、`web04` が500を返す状態で実行すると、次のようになります。

```text
$ bash health_check.sh -t targets.conf
[OK] web01 (ping)
[OK] web02 (http: 200)
[NG] web03 (ping: 応答なし)
[NG] web04 (http: 500)
[SKIP] web05 種別が不正です: pong
正常: 2件 / 異常: 2件
$ echo $?
1
```

書式で必ず守る点:

- `[OK]` `[NG]` `[SKIP]` は**半角の角かっこ**で囲み、そのあとに**半角スペース1つ**を空けて表示名を書く
- 表示名のあとも**半角スペース1つ**、かっこは**半角の `( )`**
- `http` のときはコロン+半角スペースのあとにコードを書く (`(http: 200)`)
- 集計行の区切りは ` / ` (半角スペース+スラッシュ+半角スペース)、単位は `件`

### 使い方メッセージ

`-h` のとき、および引数が足りないときに表示します。「使い方」という単語を必ず含めてください。

```text
使い方: health_check.sh -t <定義ファイル>
```

定義ファイルが存在しないときのメッセージには「見つかりません」を含めてください。

```text
エラー: 定義ファイルが見つかりません: targets.conf
```

## 5. ヒント

自力で20分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: 処理の流れを日本語で分解する</summary>

やることは次の5つだけです。順番に1つずつ書けば完成します。

1. `-t` で定義ファイルのパスを受け取り、無ければエラーで終わる
2. 定義ファイルを1行ずつ読む。空行と `#` 行は飛ばす
3. 種別を見て、ping なら ping、http なら curl、それ以外なら `[SKIP]`
4. 結果に応じて `[OK]` / `[NG]` を表示し、**カウンタ変数を1増やす**
5. ループを抜けたら集計行を表示し、異常件数を見て `exit 0` / `exit 1`

カウンタは `ok_count=0` `ng_count=0` のようにループの**前**で初期化します。ループの中で初期化すると毎回0に戻ってしまいます。

</details>

<details>
<summary>ヒント2: 種別ごとの分岐の書き方</summary>

```bash
case "$type" in
    ping)
        if ping -c 1 -W 2 "$dest" > /dev/null 2>&1; then
            echo "[OK] ${name} (ping)"
            ok_count=$((ok_count + 1))
        else
            echo "[NG] ${name} (ping: 応答なし)"
            ng_count=$((ng_count + 1))
        fi
        ;;
    http)
        code="$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 "$dest")"
        # ここで 200番台かどうかを判定する
        ;;
    *)
        echo "[SKIP] ${name} 種別が不正です: ${type}"
        ;;
esac
```

`$((ok_count + 1))` は算術展開といい、計算結果を値として使う書き方です。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

usage() {
    echo "使い方: $(basename "$0") -t <定義ファイル>"
}

TARGETS_FILE=""
while getopts ":t:h" opt; do
    case "$opt" in
        t) TARGETS_FILE="$OPTARG" ;;
        h) usage; exit 0 ;;
        *) usage >&2; exit 1 ;;
    esac
done

if [[ -z "$TARGETS_FILE" ]]; then
    echo "エラー: -t で監視対象の定義ファイルを指定してください。" >&2
    usage >&2
    exit 1
fi

if [[ ! -f "$TARGETS_FILE" ]]; then
    echo "エラー: 定義ファイルが見つかりません: ${TARGETS_FILE}" >&2
    exit 1
fi

OK_COUNT=0
NG_COUNT=0

while IFS=',' read -r name type dest; do
    [[ -z "$name" || "$name" == \#* ]] && continue
    # ここで case による分岐
done < "$TARGETS_FILE"

echo "正常: ${OK_COUNT}件 / 異常: ${NG_COUNT}件"

if [[ "$NG_COUNT" -gt 0 ]]; then
    exit 1
fi
exit 0
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| 集計がいつも `正常: 0件 / 異常: 0件` になる | カウンタをループの中で `OK_COUNT=0` と初期化している。初期化はループの前に1回だけ書く |
| `[OK] web01 (ping)` の代わりに ping の実行結果が画面に出る | `> /dev/null 2>&1` を付け忘れている。判定に使うのは終了ステータスだけ |
| `unbound variable` と出る | `set -u` の状態で、初期化していない変数を使っている。`OK_COUNT=0` のように先に初期化する |
| 空行が `[SKIP]  種別が不正です:` として表示される | 空行の読み飛ばしを書き忘れている。`[[ -z "$name" ]] && continue` を先頭に置く |
| HTTPが常に `[NG]` になる | `code` に改行や余計な空白が混ざっている。`curl` に `-o /dev/null` を付けて本文を捨てているか確認する |
| 最後の1行だけ処理されない | 定義ファイルの末尾に改行が無い。`read` は改行で1行と判断するため、末尾には改行を入れる |

`./check.sh 15` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。半角スペースの数やかっこの種類が違うだけでも不合格になります。
