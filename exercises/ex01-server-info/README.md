## 1. どんな場面で必要になるか

サーバーにログインして最初にやることは、たいてい「今どのサーバーにいて、今が何時で、誰として作業しているか」の確認です。作業ログのスクリーンショットや、後で見返す作業記録にも必ず入る情報です。

複数台のサーバーを扱うようになると、**別のサーバーだと思い込んで作業していた**という事故が起きます。実務ではこれを防ぐために「作業の最初に環境情報を出力する小さなスクリプト」をよく用意します。

この演習では、その最小版を自分の手で書きます。案件No.1のスクリプト(`create_users.sh`)も、冒頭で実行環境を確認してからログに書き出すという同じ考え方で作られています。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| シバン(`#!/bin/bash`) | 「このファイルはbashで動かす」という宣言。1行目に必ず書く |
| 変数 | `NAME="web01"` のように値を入れる箱。使うときは `"$NAME"` |
| コマンド置換 | `$(コマンド)` と書くと、そのコマンドの実行結果が文字列として入る |
| 引数 | 実行時に渡す値。`$1` が1個目、`$#` が個数 |
| 終了ステータス | 処理の成否を数字で返す仕組み。成功=0、失敗=0以外 |
| 標準エラー出力 | エラーメッセージの出力先。`>&2` を付けて出す |

### 3分でわかる予備知識

**変数とクォート**

```bash
NAME="web01"          # 代入するときは $ を付けない。= の前後に空白を入れない
echo "$NAME"          # 使うときは $ を付ける。必ずダブルクォートで囲む
```

`"$NAME"` のようにダブルクォートで囲む理由は、値に空白が含まれていても1つの文字列として扱うためです。囲み忘れは初心者が最もハマるポイントなので、**変数は常にダブルクォートで囲む**と覚えてしまってください。

**コマンド置換**

```bash
NOW=$(date '+%Y-%m-%d %H:%M:%S')   # date コマンドの出力が NOW に入る
echo "$NOW"                        # → 2026-09-06 12:34:56
```

**引数と終了ステータス**

```bash
$0   # スクリプト自身の名前
$1   # 1個目の引数
$#   # 引数の個数
exit 0   # 成功として終了
exit 1   # 失敗として終了
```

終了ステータスは、人間には見えにくい代わりに **cronやCI/CDなどの「呼び出し側」が成否を判断するための唯一の手段**です。直前のコマンドの終了ステータスは `echo $?` で確認できます。

## 3. 課題

`work/server_info.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 引数を1つ(サーバー名)付けて実行 | サーバー情報を標準出力に表示し、終了ステータス `0` で終わる |
| 2 | 引数なしで実行 | 使い方を**標準エラー出力**に表示し、終了ステータス `1` で終わる |
| 3 | 引数が2つ以上 | 引数なしと同じ扱い(使い方を表示して `1`) |
| 4 | `-h` または `--help` を指定 | 使い方を**標準出力**に表示し、終了ステータス `0` で終わる |

### 出力フォーマット(仕様1のとき)

```text
===== サーバー情報 =====
サーバー名: web01
ホスト名: ubuntu-vm
実行日時: 2026-09-06 12:34:56
実行ユーザー: ubuntu
```

- 「サーバー名」は引数で受け取った文字列をそのまま表示する
- 「ホスト名」は `hostname` コマンドの実行結果
- 「実行日時」は `date` コマンドで `YYYY-MM-DD HH:MM:SS` 形式
- 「実行ユーザー」は `whoami` コマンドの実行結果
- ラベルと値の区切りは **半角コロン+半角スペース**(`サーバー名: web01`)

### 使い方メッセージ(仕様2〜4のとき)

「使い方」という単語を必ず含めてください。例:

```text
使い方: server_info.sh <サーバー名>
```

## 5. ヒント

自力で15分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: 引数の個数をどう調べるか</summary>

引数の個数は `$#` に入っています。「1個ではないとき」は次のように書けます。

```bash
if [[ "$#" -ne 1 ]]; then
    # ここでエラー処理
fi
```

`-ne` は「not equal(等しくない)」の意味です。数値の比較には `-eq`(等しい) `-ne` `-lt`(より小さい) `-gt`(より大きい)を使います。

</details>

<details>
<summary>ヒント2: 標準エラー出力への出し方と、-h の判定</summary>

標準エラー出力に出すには、`echo` の後ろに `>&2` を付けます。

```bash
echo "使い方: $(basename "$0") <サーバー名>" >&2
```

`-h` と `--help` の両方を受け付けるには `case` 文が便利です。

```bash
case "${1:-}" in
    -h|--help)
        echo "使い方: ..."      # こちらは標準出力(>&2 を付けない)
        exit 0
        ;;
esac
```

`${1:-}` は「$1 が未定義なら空文字として扱う」という書き方です。`set -u` を付けているスクリプトで未定義の引数を参照してもエラーにならないようにするための定番です。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

usage() {
    echo "使い方: $(basename "$0") <サーバー名>"
}

case "${1:-}" in
    -h|--help) usage; exit 0 ;;
esac

if [[ "$#" -ne 1 ]]; then
    usage >&2          # 関数の出力全体を標準エラーに向けることもできる
    exit 1
fi

SERVER_NAME="$1"
# ここで hostname / date / whoami の結果を変数に入れて表示する
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `command not found` と出る | `NAME = "web01"` のように `=` の前後に空白を入れている。空白を入れずに `NAME="web01"` と書く |
| 変数が空で表示される | 代入するときに `$` を付けている(`$NAME="web01"` は誤り) |
| 日付の形式が合わない | `date '+%Y-%m-%d %H:%M:%S'` のように、フォーマット文字列はシングルクォートで囲む |
| 引数なしでも終了ステータスが0 | `exit 1` を書き忘れている。`echo $?` で確認する |
| エラーメッセージが標準出力に出てしまう | `>&2` を付け忘れている |

`./check.sh 01` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。
