## 1. どんな場面で必要になるか

深夜2時。あるサーバーのディスクが満杯になり、アプリケーションが1秒間に数十行の ERROR をログに吐き始めました。ex11 で作ったような検知スクリプトがそれを見つけ、1行ごとに担当者へ通知を送ります。結果、担当者のスマートフォンは朝まで鳴り続け、Slackのチャンネルは同じメッセージで数千件埋まりました。

原因は1つの障害なのに、通知は数千通。これでは他のチームの重要な連絡も埋もれてしまいます。この現象を **アラートストーム** と呼び、監視を導入した現場が最初にぶつかる失敗の定番です。

対策は「一度通知したら、しばらくは同じ通知を送らない」という仕組みで、**スロットリング**(通知の間引き)と言います。実装の要になるのが **状態ファイル** です。スクリプトは実行が終わると記憶をすべて失うので、「前回いつ通知したか」をファイルに書き残しておき、次の実行でそれを読み直します。この演習では、その最小版を自分の手で書きます。案件No.3の `log-watch-alert.sh` にも、まったく同じ仕組みが `handle_match()` として入っています。

## 2. この演習で学ぶこと

| 学ぶこと | ひとことで言うと |
|---|---|
| 状態ファイル | 実行が終わっても消えない「メモ帳」。次回の実行に情報を引き継ぐ |
| epoch秒 | 1970年1月1日からの経過秒数。`date +%s` で取れる。引き算するだけで経過時間が出せる |
| 算術式 `$(( ))` | 数値計算をする書き方。`ELAPSED=$(( NOW - LAST ))` |
| 環境変数で設定を外に出す | `${THROTTLE_SEC:-300}` で「指定が無ければ300」。テストや本番で値だけ差し替えられる |
| 正規表現による数値チェック | 状態ファイルが壊れていても落ちないようにするための防御 |
| 防御的プログラミング | 「入力は壊れているかもしれない」を前提に書く。無人で動くスクリプトの必須作法 |

### 3分でわかる予備知識

**epoch秒(エポック秒)**

`date +%s` は「1970年1月1日 00:00:00 から今までの秒数」を返します。ただの数字なので、引き算するだけで経過時間が分かります。

```bash
NOW="$(date +%s)"       # 例: 1788672000
echo "$NOW"
```

日付文字列(`2026-09-06 10:00:00`)のままだと引き算できません。**時間の差を計算したいときは epoch秒に直す**、と覚えてください。

**算術式 `$(( ))`**

```bash
NOW=1788672000
LAST=1788671900
ELAPSED=$(( NOW - LAST ))    # → 100
echo "${ELAPSED}秒経過"
```

`$(( ))` の中では変数に `$` を付けても付けなくてもかまいません。

**環境変数で既定値を上書きできるようにする**

```bash
THROTTLE_SEC="${THROTTLE_SEC:-300}"
```

これは「環境変数 `THROTTLE_SEC` が設定されていればその値、無ければ `300`」という意味です。こう書いておくと、スクリプトを書き換えずに動きを変えられます。

```bash
THROTTLE_SEC=60 ./throttle.sh "テスト"    # この実行だけ60秒間隔になる
```

本番では systemd の `EnvironmentFile=` から、テストでは手で `export` して値を渡す、という使い分けができます。

**状態ファイルは壊れている前提で読む**

状態ファイルは、書き込みの途中で電源が落ちたり、誰かが手で編集したりして壊れることがあります。中身が `abc` のときに何も考えず引き算すると、こうなります。

```bash
LAST="abc"
echo $(( 1788672000 - LAST ))
# → bash: abc: 未割り当ての変数です  (エラーで異常終了する)
```

障害の真っ最中に通知スクリプト自体が落ちるのは最悪です。そこで **読み込んだ値が数字かどうかを必ず確かめて**、おかしければ「前回通知なし」として扱います。

```bash
if [[ "$LAST" =~ ^(0|[1-9][0-9]*)$ ]]; then
    echo "数値として正しい"
fi
```

`[[ 文字列 =~ 正規表現 ]]` は「文字列が正規表現に一致するか」の判定です。`^` が行頭、`$` が行末なので、これで「全体が数字だけ」を表せます。単に `^[0-9]+$` としないのは、`008` のような **先頭に0が付いた値を弾く** ためです。bashの算術式は先頭が `0` の数を8進数として解釈するので、`008` は「8進数として無効」でエラーになってしまいます。

## 3. 課題

`work/throttle.sh` を編集し、次の仕様を満たすスクリプトを完成させてください。

### 仕様

| No. | 条件 | 期待する動作 |
|---|---|---|
| 1 | 引数(メッセージ)が無い | 使い方を**標準エラー出力**に出し、終了ステータス `1` |
| 2 | 状態ファイルの場所 | 既定は `./throttle.state`。環境変数 `STATE_FILE` が設定されていればそちらを使う |
| 3 | 抑止間隔 | 既定は `300` 秒。環境変数 `THROTTLE_SEC` が設定されていればその値を使う |
| 4 | 状態ファイルが無い / 中身が空 / 数字でない | エラーで落ちず、「前回通知なし」として扱う |
| 5 | 前回通知なし、または経過秒が抑止間隔以上 | `通知しました: <メッセージ>` を**標準出力**に出す |
| 6 | 仕様5で通知したとき | 状態ファイルに現在時刻(epoch秒)を書き込み、終了ステータス `0` |
| 7 | 経過秒が抑止間隔より小さい | `抑止しました: 前回の通知から <経過秒>秒しか経っていません (抑止間隔: <抑止間隔>秒)` を**標準出力**に出す |
| 8 | 仕様7で抑止したとき | 状態ファイルは**更新しない**。終了ステータスは `0` |

### 実行例 / 出力フォーマット

```text
$ ls throttle.state
ls: 'throttle.state' にアクセスできません: そのようなファイルやディレクトリはありません

$ ./throttle.sh "ディスク使用率が90%を超えました"
通知しました: ディスク使用率が90%を超えました
$ echo $?
0

$ cat throttle.state
1788672000

$ ./throttle.sh "ディスク使用率が90%を超えました"
抑止しました: 前回の通知から 3秒しか経っていません (抑止間隔: 300秒)
$ echo $?
0

$ THROTTLE_SEC=1 ./throttle.sh "ディスク使用率が90%を超えました"
通知しました: ディスク使用率が90%を超えました
```

書式の決まりは次のとおりです。テストはこの文字列をそのまま見ています。

- 通知の書式は `通知しました: ` (半角コロン+半角スペース) のあとに受け取ったメッセージをそのまま続ける
- 抑止の書式は `抑止しました: 前回の通知から ` + 経過秒 + `秒しか経っていません (抑止間隔: ` + 抑止間隔 + `秒)`
  - **「前回の通知から」と数値の間に半角スペースが1つ入る**。カッコは半角の `( )` を使う
  - `(抑止間隔: 300秒)` の部分は、`THROTTLE_SEC` に指定された値をそのまま表示する
- 状態ファイルに書き込むのは **epoch秒の数字だけ**(`1788672000`)。日付文字列や余計なラベルは書かない
- 使い方のメッセージには「使い方」という単語を必ず含める。例: `使い方: throttle.sh <メッセージ>`

### 抑止するかどうかの判定

```text
経過秒 = 現在時刻(epoch秒) - 状態ファイルに書かれた前回通知時刻(epoch秒)

  前回通知なし          → 通知する
  経過秒 >= 抑止間隔    → 通知する(そして状態ファイルを現在時刻で更新する)
  経過秒 <  抑止間隔    → 抑止する(状態ファイルはそのまま)
```

## 5. ヒント

自力で20分考えてから開いてください。段階的に答えに近づくよう3段階に分けています。

<details>
<summary>ヒント1: 処理の流れを整理する</summary>

やることを日本語で並べると、次の6段階になります。

1. 設定値を決める(`STATE_FILE` と `THROTTLE_SEC` を環境変数で上書きできる形にする)
2. 引数が無ければ使い方を標準エラー出力に出して `exit 1`
3. 現在時刻を epoch秒で取る
4. 状態ファイルがあれば読む。**読んだ値が数字でなければ「前回通知なし」に倒す**
5. 前回通知があり、かつ経過秒が抑止間隔より小さければ、抑止メッセージを出して `exit 0`
6. そうでなければ通知メッセージを出し、状態ファイルに現在時刻を書いて `exit 0`

いちばん間違えやすいのは4です。「ファイルが無い」「中身が空」「中身が数字でない」の3つを**同じ扱い(前回通知なし)にまとめてしまう**と、コードがぐっと短くなります。

</details>

<details>
<summary>ヒント2: 使う文法の具体例</summary>

**環境変数で上書きできる既定値**

```bash
STATE_FILE="${STATE_FILE:-./throttle.state}"
THROTTLE_SEC="${THROTTLE_SEC:-300}"
```

**状態ファイルを読む**

```bash
LAST_NOTIFIED=""
if [[ -f "$STATE_FILE" ]]; then
    LAST_NOTIFIED="$(head -n 1 "$STATE_FILE")"
fi
```

`head -n 1` を使うと、余計な行が入っていても先頭行だけを読めます。

**数字かどうかを確かめる**

```bash
if [[ ! "$LAST_NOTIFIED" =~ ^(0|[1-9][0-9]*)$ ]]; then
    LAST_NOTIFIED=""       # 数字でなければ「前回通知なし」に倒す
fi
```

**状態ファイルに書き込む**

```bash
printf '%s\n' "$NOW" > "$STATE_FILE"
```

`>` は上書き。`>>` の追記にしてしまうと行がどんどん増えるので注意してください。

</details>

<details>
<summary>ヒント3: 全体の骨組み</summary>

```bash
#!/bin/bash
set -u

STATE_FILE="${STATE_FILE:-./throttle.state}"
THROTTLE_SEC="${THROTTLE_SEC:-300}"

usage() {
    echo "使い方: $(basename "$0") <メッセージ>"
}

if [[ "$#" -lt 1 ]]; then
    usage >&2
    exit 1
fi
MESSAGE="$1"

NOW="$(date +%s)"

LAST_NOTIFIED=""
# 状態ファイルがあれば読み、数字でなければ空に戻す

if [[ -n "$LAST_NOTIFIED" ]]; then
    ELAPSED=$(( NOW - LAST_NOTIFIED ))
    if [[ "$ELAPSED" -lt "$THROTTLE_SEC" ]]; then
        # 抑止メッセージを出して exit 0(状態ファイルは触らない)
        :
    fi
fi

# ここまで来たら通知する。メッセージを出して、状態ファイルに $NOW を書く
```

</details>

## 6. よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| `bash: abc: 未割り当ての変数です` と出る | 状態ファイルの中身を数値チェックせずに `$(( ))` に渡している。`[[ =~ ^(0\|[1-9][0-9]*)$ ]]` で確認する |
| `throttle.sh: 行XX: $1: 未割り当ての変数です` と出る | `set -u` を付けた状態で引数チェックより先に `$1` を参照している。個数チェックを先に書く |
| 何度実行しても毎回「通知しました」になる | 状態ファイルへの書き込みができていない。`cat throttle.state` で中身を確認する |
| 2回目以降ずっと抑止されたままになる | 通知したときに状態ファイルを更新していない。抑止したときは**更新しない**のが正しい |
| 経過秒がマイナスや巨大な値になる | 状態ファイルに日付文字列を書いている。書き込むのは `date +%s` の値(数字だけ) |
| 抑止メッセージの秒数が合わない | `(抑止間隔: ...)` に表示するのは経過秒ではなく `THROTTLE_SEC` の値 |

`./check.sh 12` が失敗したときは、**「期待」と「実際」の差分**を必ず読んでください。どこがどう違うかがそのまま書かれています。

## 7. 発展課題(採点対象外)

余裕がある人向けの追加課題です。実務では「もう一歩の気配り」が評価されます。

1. 抑止した回数も状態ファイルに記録し、次に通知するときに `※このほか 12 件の検知を抑止しました` を付ける(案件No.3の実装と同じ形)
2. メッセージの種類ごとに別々の状態ファイルを使い、`ディスク` と `CPU` の通知が互いを抑止しないようにする
3. 状態ファイルの書き込みを「一時ファイルに書いてから `mv` で置き換える」方式にして、書き込み途中で中断されても壊れないようにする
