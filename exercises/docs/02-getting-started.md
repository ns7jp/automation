# はじめかた

環境の準備から、最初の1問(ex01)を自力で解ききるところまでを、迷わないように順を追って説明します。**所要時間は環境準備を含めて1〜2時間**です。

---

## 1. 必要なもの

必要なのは次の2つだけです。

| 必要なもの | 確認方法 |
|---|---|
| Linuxのターミナル(bashが動く環境) | `bash --version` でバージョンが表示されること |
| テキストエディタ | `nano` / `vim` / VS Code など、何でもよい |

**不要なもの**: root権限、サーバー、クラウドアカウント、インターネット接続(初回のclone時を除く)、Docker、プログラミング言語の処理系。

---

## 2. 環境を用意する

すでにLinuxのターミナルが使える人は、この章を飛ばして「3. 演習パックを取得する」に進んでください。

### 2.1 どれを選ぶか

| 使っているPC | おすすめ | 理由 |
|---|---|---|
| Windows | **WSL2 + Ubuntu** | インストールが最も速い。演習パックは全21演習がWSL2で動く |
| macOS | **標準のターミナル** | 最初から bash / zsh が使える。追加インストール不要 |
| どれでも | 仮想マシン(VirtualBox + Ubuntu Server) | 案件パックまで見据えるならこれ。壊してもやり直せる |

**演習パックだけならWSL2やmacOSのターミナルで十分です。** 仮想マシンが必要になるのは、案件パックで実際にサーバーを構築する段階からです(その手順は [../../docs/04-environment-setup.md](../../docs/04-environment-setup.md) にあります)。

### 2.2 Windows: WSL2をインストールする

PowerShell を「管理者として実行」で開き、次を実行します。

```powershell
wsl --install -d Ubuntu
```

再起動後、Ubuntuが起動してユーザー名とパスワードを聞かれるので設定します。以降は、スタートメニューの「Ubuntu」からターミナルを開けます。

```bash
# 動作確認
$ bash --version
```

```text
# 実行結果イメージ
GNU bash, version 5.2.21(1)-release (x86_64-pc-linux-gnu)
```

### 2.3 macOS: 標準のターミナルを使う

「アプリケーション」→「ユーティリティ」→「ターミナル」を開きます。

macOSの標準シェルは zsh ですが、演習パックはすべて `bash` を明示して実行するため、そのままで問題ありません。ただしmacOS標準のbashはバージョンが古い(3.2)ため、一部の演習で挙動が異なる可能性があります。気になる場合は Homebrew で新しいbashを入れてください。

```bash
$ brew install bash
```

### 2.4 macOSでの注意点

演習パックは Linux の GNU コマンドを前提に書かれています。macOSの一部コマンド(`date`、`sed`、`stat` など)はオプションが異なるため、次のいずれかを推奨します。

- **推奨**: WSL2、仮想マシン、またはクラウドのUbuntuで進める
- Homebrew で GNU 版コマンドを入れる (`brew install coreutils gnu-sed`)

## 3. 演習パックを取得する

```bash
$ git clone https://github.com/ns7jp/automation.git
$ cd automation/exercises
```

Gitが入っていない場合は先に入れてください。

```bash
$ sudo apt update && sudo apt install -y git
```

取得できたら、動作確認を兼ねて演習の一覧を表示します。

```bash
$ ./check.sh --list
```

```text
# 実行結果イメージ
演習一覧 (全21件)

ステージ1: Bashの基礎体力
  ex01  ★☆☆☆☆     サーバー情報表示スクリプト
        目安30分 / 変数 / コマンド置換 / 引数チェック / 終了ステータス
  ...
```

`Permission denied` と出た場合は、実行権限を付けるか `bash` を付けて実行してください。

```bash
$ chmod +x check.sh        # 実行権限を付ける
$ bash check.sh --list     # または bash 経由で実行する
```

## 4. 最初の1問(ex01)を解ききる

ここからは実際の流れを追いかけます。**同じ手順で残り20問も進められます。**

### 手順1: 課題文を読む

```bash
$ cat ex01-server-info/README.md
```

エディタやGitHub上で読んでも構いません。読むときは次の3か所を必ず確認してください。

1. **「3. 課題」の仕様表** — 何を作るのか
2. **出力フォーマット** — どういう文字列を出すのか(テストはここを見ています)
3. **「2. この演習で学ぶこと」の3分でわかる予備知識** — 知らない文法はここで解決します

### 手順2: 採点だけ先に実行してみる

まだ何も書いていない状態で採点すると、どこを目指せばよいかが分かります。

```bash
$ ./check.sh 01
```

```text
# 実行結果イメージ
  ✓ [1] bashの構文エラーがない
  ✗ [2] 引数なしで実行すると終了ステータス1で終わる
      期待: 終了ステータス 1
      実際: 終了ステータス 0
      ヒント: 引数の個数は $# で調べます。1個でなければ exit 1 で終了してください。
  ...
  結果: 7/15 合格
```

**この失敗一覧が、そのままToDoリストになります。** 上から1つずつ潰していきましょう。

### 手順3: 雛形を編集する

```bash
$ nano ex01-server-info/work/server_info.sh
```

雛形には `TODO 1:` `TODO 2:` … と番号が振られ、何をすべきかが日本語で書かれています。上から順に埋めてください。

nano の基本操作: 編集して `Ctrl+O` → `Enter` で保存、`Ctrl+X` で終了。

### 手順4: 手で動かしてみる

採点する前に、自分で実行して目で確かめる癖をつけてください。**この確認の速さが、そのままデバッグの速さになります。**

```bash
$ bash ex01-server-info/work/server_info.sh web01
$ echo $?          # 直前のコマンドの終了ステータスを確認する
```

### 手順5: 採点する

```bash
$ ./check.sh 01
```

不合格なら手順3に戻ります。**15分考えても分からなければ、READMEの「5. ヒント」を1段だけ開いてください。**

### 手順6: 合格したら解答例を読む

```bash
$ cat ex01-server-info/answer/server_info.sh
```

合格して終わりにせず、必ず解答例を読んでください。同じ仕様でも、実務でよく使われる書き方があります。解答例のコメントには「なぜそう書くか」が書かれています。

### 手順7: 記録を残す

[05-progress-sheet.md](05-progress-sheet.md) の学習記録シートに、**詰まった点と、どう解決したか**を1〜2行で書き残してください。これが後で面接のエピソードになります。

## 5. 学習のリズム

| ペース | 1日の目安 | 全21演習の完了目安 |
|---|---|---|
| 平日に1時間 | 1〜2演習 | 約3週間 |
| 週末中心(土日に4時間ずつ) | 3〜4演習 | 約3週間 |
| 集中(1日5時間) | 4〜5演習 | 約5日 |

全21演習の合計は約18〜20時間です。**平日に学ぶ場合は1日2演習まで、まとまった時間が取れる日でも1日4演習程度まで**にしておくことをおすすめします。詰まって考えている時間が学習そのものであり、消化不良のまま先に進むと、ステージ3以降で必ず戻ることになります。

### ステージが終わったら

ステージを1つ終えるたびに、対応する案件のREADMEと設計書を読んでください。演習で書いた部品が、実際のスクリプトの中でどう組み合わさっているかが見えます。

```bash
# 例: ステージ1(ex01-ex06)が終わったら
$ cat ../projects/01-user-account-automation/README.md
$ cat ../projects/01-user-account-automation/src/create_users.sh
```

## 6. つまずいたときの順番

1. `./check.sh NN` の**失敗メッセージを最後まで読む**
2. 演習READMEの「5. ヒント」を**1段だけ**開く
3. 演習READMEの「6. よくあるつまずき」を見る
4. [06-hints-and-pitfalls.md](06-hints-and-pitfalls.md)(全演習共通のつまずき集)を見る
5. [07-bash-syntax-cheatsheet.md](07-bash-syntax-cheatsheet.md) で文法を確認する
6. `answer/` の解答例を読む。**読んで理解し、写経してから、閉じてもう一度自力で書く**

### デバッグの基本ワザ3つ

演習中に必ず役立つ3つです。覚えておいてください。

```bash
# 1. 実行内容を1行ずつ表示する(どこまで進んだか分かる)
$ bash -x ex01-server-info/work/server_info.sh web01

# 2. 実行せずに文法だけ確認する(fi や done の閉じ忘れを見つける)
$ bash -n ex01-server-info/work/server_info.sh

# 3. 直前のコマンドの終了ステータスを見る
$ echo $?
```

## 7. よくある質問

**Q. 解答例を見てしまったら意味がないのでは?**

A. そんなことはありません。読んで理解し、**閉じてから自力で書き直せたなら、それは習得です**。写経すらできない状態で悩み続けるほうが時間の損失です。ただし「コピーして貼り付けて合格」だけは避けてください。

**Q. 順番どおりにやらないと駄目ですか?**

A. ステージ1(ex01-ex06)は順番どおりを強く推奨します。後の演習が前の演習の文法を前提にしているためです。ステージ2以降は、興味のあるステージから入っても構いません。

**Q. 採点は自分のPCを壊しませんか?**

A. 壊しません。採点は使い捨ての一時ディレクトリの中だけで行われ、その外には一切書き込みません。さらに `useradd` や `ping` や `curl` のように、本物を動かすと影響が大きいコマンドはダミーに差し替えられています(`rm` などのファイル操作は本物が動きますが、対象は一時ディレクトリの中だけです)。詳細は [04-self-check-guide.md](04-self-check-guide.md) を参照してください。

**Q. 全部終わったら何をすればいいですか?**

A. [../README.md](../README.md) の「7. 修了チェック」を確認し、案件パックの案件No.1へ進んでください。
